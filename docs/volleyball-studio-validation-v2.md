# Проверка обновления — 29 октября 2026

Обновление выполнено по новому заданию Worker. Существующие модели, CUDA и Python-окружение не переустанавливались. Проверено в Windows → WSL Ubuntu-25.04: Python 3.14.7, ONNX Runtime 1.31.1, OpenVINO 2026.2.1, OpenCV 5.0.0, FFmpeg 7.1.1. GPU: NVIDIA GeForce RTX 5070 Ti Laptop GPU, 12227 MiB, 32 доступных CPU-потока. В WSL при замерах было около 12 ГБ свободной RAM; это не вся физическая память компьютера.

## Что реально добавлено

- Отдельный `analysis/events.json`, game-tracks и статусы этапов; контакты для VFX/звука берутся из событий, а не вычисляются во время монтажа.
- Минимальная длительность отбора отделена от базовой сегментации: её изменение не запускает нейросети.
- Classic, Dynamic, Cinematic; пять вопросов CLI теперь включают стиль.
- HTML-монтажный лист, миниатюры, таймкоды, score, include/exclude по ID.
- Player motion и изменения направления в рейтинге, защита от копий исходника, ограниченный контекст до соседних треков.
- Отдельный VFX-модуль, затухание огня, масштабирование по разрешению, консервативный bbox-guard, shake, плавный zoom, титр и цветокоррекция.
- Событийный speed ramp перед/после удара; звук следует той же интервальной карте, включая ускорение.
- Sidechain ducking и работа без музыкального файла.
- До двух независимых процессов монтажа с учётом RAM, телеметрия RAM/VRAM, общий прогресс A–I.
- Benchmark реального фрагмента и опциональный Linux scratch для прокси.
- QC до публикации результата; одна попытка CPU-перекодирования при ошибке.

## Производительность

Сравнение последовательного и параллельного монтажа: тот же 30-секундный исходник, те же два отобранных эпизода, Dynamic, музыка, 360×640, NVENC, готовый CV-кэш. Один worker: **18.9606 с**; два worker: **14.9285 с**, сокращение примерно на **21.3%**. Время включает работу CLI и QC, а не только кодировщик. Это один парный замер, а не статистически устойчивое обещание ускорения.

Отдельный benchmark холодного реального 10-секундного участка:

| Измерение | Время |
| --- | ---: |
| ONNX CUDA, запуск процесса + загрузка + обработка | 14.6283 с |
| VballNet OpenVINO CPU, тот же участок | 11.8883 с |
| libx264, 360×640 | 0.3452 с |
| NVENC, 360×640 | 1.1461 с |
| Декодирование через `/mnt/c` | 0.1337 с |
| Декодирование через Linux tmp | 0.1213 с |
| Копирование прокси в Linux tmp | 0.0385 с |

На этом коротком участке копирование не окупилось, поэтому Linux scratch по умолчанию не включён. Для короткого холодного preview CPU оказался быстрее; длительные матчи и 1080p требуют отдельного замера, GPU не заменён автоматически. Два worker выбраны как верхняя автоматическая граница, а не стремление к 100% загрузке оборудования.

Полный benchmark JSON: `studio_work/benchmark_*/benchmark.json`. До/после сравнивались одинаковые параметры монтажа; ранние результаты первой версии с другими разрешениями не использовались для заявления об ускорении.

## Найденные и исправленные ошибки

Во время многовидеотеста обнаружено различие имён CSV у OpenVINO и ONNX. Добавлен адаптер `analysis_predict_ball.csv` → канонический `ball/analysis/ball.csv`; исправный CPU-прогон повторён. Ошибка завершённого подпроцесса без ожидаемого файла теперь также получает status failed. Частичный запуск после ошибки одного видео сохраняет status partial, а не подменяет его complete.

## Известные ограничения

Готовый технический конвейер не доказывает качество спортивного отбора. В ранней версии наблюдалось ложное принятие подготовки за игру; на текущем ракурсе основной crop может следовать неточной траектории. Обзорное окно сохраняет контекст, но не исправляет детектор. Ручной просмотр остаётся полезным.

Автоматическая геометрия площадки, точная сегментация перекрытий, компенсация движущейся камеры, физическая скорость в м/с, универсальная pose/action классификация, perceptual dedup, beat matching, HDR tone mapping и LUFS mastering не реализованы. Путь с ручной court JSON не проверен на этих исходниках: соответствующая разметка не предоставлена. Native Windows Python и TensorRT не объявляются проверенными.

QC проверяет потоковые тайминги и общую карту аудио/видео, но не доказывает слышимое совпадение каждого реального удара. Ни один внешний VFX/AI-сервис не использовался. Длинные матчи целиком не прогонялись: проверен полный цикл на коротких реальных фрагментах.
