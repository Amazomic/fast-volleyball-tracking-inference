# Доказательства улучшения конечного результата

**Нет публичного полного датасета с разметкой матчей в этом репозитории.**
CI не делает вид, что синтетические трассы измеряют реальную точность модели.

## Минимальная схема данных (без личных имён и исходного видео)

Файл аннотаций `annotations.json` (может храниться вне Git):
```json
{
  "schema": "volley-quality-annotations/1",
  "dataset_id": "anonymized-amateur-match-set",
  "clip_id": "clip-001",
  "touches": [{"time_sec": 1.2}, {"time_sec": 2.8}],
  "rallies": [{"start_sec": 0.5, "end_sec": 4.0}]
}
```

Два файла результатов `before.json` и `after.json` имеют тот же
`clip_id`, поля `touches` и `rallies`, а также при наличии подтверждённых
назначений `identity_samples` с `time_sec`, `person_id` и `track_id`.
Не включать лицо/имя реального человека в публичные фикстуры.

```bash
python scripts/ci/quality_eval.py \
  --annotations /private/annotations.json \
  --baseline /private/before.json \
  --candidate /private/after.json \
  --baseline-revision 3 --candidate-revision 4 \
  --output docs/quality/reports/clip-001-r4.json
```

Отчёт содержит SHA256 входных файлов, TP/FP/FN касаний и P/R/F1,
среднюю ошибку двух границ розыгрыша, пропущенные/лишние розыгрыши,
изменения Track ID внутри окна 3 сек и слияния разных людей в один
Track ID в один момент времени. Отсутствие ID-разметки обозначается
`null`, а не нулём. Измеритель нельзя запускать на вымышленных
аннотациях и называть такой результат реальным бенчмарком.

## Golden CPU defaults

При изменении `scripts/volleyball_ui/static/cpu-defaults.json` PR policy
требует новую ревизию, строку отчёта в
`docs/CPU_GOLDEN_DEFAULTS.md` и машиночитаемый отчёт с теми же ревизиями.
Ревьюер обязан подтвердить происхождение разметки и сопоставимость
условий. Автоматическая валидация схемы **не удостоверяет** истинность
пользовательской разметки или итогового видео.

На текущем этапе честно отмечать `NOT MEASURED`, если нет разметки:
алгоритм нельзя назначить новым золотым только из-за скорости,
красивого графика или проходящих unit-тестов. Исходный эталон
замораживается до появления достаточного набора реальных матчей.

Для нормальной приёмки вручную сравнить целые розыгрыши с предыдущей
версией, выбрать пару сцен с окклюзиями/выходом игроков из кадра,
а также сцены с прямолинейным пролётом мяча рядом с игроком.
