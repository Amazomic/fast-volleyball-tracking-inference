# Этап 84/85 — реальные видео и Python/Rust-паритет

**Дата: 2026-11-09. Приёмочный вердикт: NO-GO.**
Выполнены инструментарий проверки, архивный аудит Python и короткий
реальный монтажный тест. Точность касаний, Track ID и розыгрышей на
размеченном матче, полный CUDA-инференс и сравнение Python/Rust
**не подтверждены**. Номер этапа не означает готовность production.

## Проверенное настоящее видео

Источник: Python-подготовленный медиакэш
results/prepared/fa5883350411c05b62783a4b43ac.mp4,
150+ MB, H.264/AAC, 1280×720, 30 FPS, 544.608 секунд.
Полный SHA-256 сохранён в docs/RUST_BENCHMARK_84_MEDIA.json.
Это не та же запись, на которой остался исторический Python baseline.

Rust release на отдельном loopback-порту в одноразовом /tmp-проекте
отрендерил оригинальный фрагмент 12–18 с вертикально (aspect-fit,
letterbox без обрезки), с созданной только для теста аудиодорожкой.
Все оригинальные проекты и исходные видео остались неизменными.

| Показатель | Наблюдение |
|---|---|
| Нативный Rust-монтаж 6 секунд | **1.829 с**, 3.281× реального времени |
| Готовый MP4 | 406×720, H.264/AAC, 30 FPS, 6.0 с, 180 кадров |
| Fidelity: SSIM относительно оригинала | **0.99793** (180 кадров; согласованный 9:16 letterbox) |
| Источник | original_recording, проверен Rust selection.json |
| SHA-256 выхода | 7e13fb54797498a8c49454de2b760eed9f508975291cde2abe267a6ea85183c4 |
| RSS Rust-сервера в коротком тесте | 8.11 MiB, БЕЗ подтверждённого FFmpeg RSS |
| Полный RAM/VRAM peak | **не измерен** |

SSIM относится **только к картинке и монтажу**, не к качеству Touch,
ReID или началу/окончанию розыгрышей. Это не Python/Rust speedup:
Python Studio не запускалась на том же самом видео, профиле и диапазоне.
Фактические machine-readable измерения и предупреждения о неполном
замере памяти находятся в docs/RUST_BENCHMARK_84_MEDIA.json.

## Дальнейшая воспроизводимая приёмка

Файлы:
- scripts/ci/test_rust_real_media_84.mjs — реальное сохранённое
  видео, Rust API, 180 кадров, SSIM, H.264/AAC, происхождение, SHA.
- scripts/ci/audit_python_baseline_84.mjs — SHA исторических
  Python predictions, без статуса независимой разметки.
- scripts/ci/benchmark_rust_parity_84.mjs — строгий оценщик
  Touch ±0.15 с, Rally IoU ≥0.5, глобальный IDF1 с
  покадровыми bbox IoU ≥0.5 и Hungarian assignment (смена Track ID
  наказуема). Неразмеченные кадры исключаются из IDF1.
- scripts/ci/test_rust_parity_84.mjs — математические тесты формул
  на ИСКУССТВЕННЫХ fixtures; не результаты матча.
- scripts/ci/test_rust_benchmark_84.mjs — системная проверка SHA,
  архивных фактов и строгого NO-GO.

Команды в WSL, из корня репозитория:

    node scripts/ci/test_rust_real_media_84.mjs --out docs/RUST_BENCHMARK_84_MEDIA.json
    node scripts/ci/audit_python_baseline_84.mjs --out docs/RUST_BENCHMARK_84_PYTHON.json
    node scripts/ci/test_rust_benchmark_84.mjs --with-media
    node scripts/ci/test_rust_benchmark_84.mjs --require-parity

Последняя команда ДОЛЖНА вернуть код 3 / NO-GO до устранения
блокеров. Архивная ручная разметка должна быть независимой от
модельных предсказаний. Требуется одинаковый видео SHA-256,
период, FPS, модельные веса, golden-параметры, независимый
SHA меток и предсказаний, измеренные время/RSS/VRAM и полный
проверенный аудио/видео-монтаж.

Предварительные пороги для этапа 85: Touch F1, global IDF1,
Rally F1 не должны быть хуже Python более чем на 0.02 абсолютных
пункта; время, peak RSS и peak VRAM не должны превышать 110%
Python на одинаковой машине и диапазоне. Исходный медиапоток,
длительность, качество кадров, разрешение и звук должны быть
подтверждены; Docker и CUDA интеграция обязаны пройти.
Статус GO_CANDIDATE всё ещё требует отдельного решения этапа 85.
Оценщик никогда не переключает production самостоятельно.
