# Проверка upstream e9c94bc (04.11.2026) в Volley Studio

## Профиль

Глобальный профиль: **Upstream 04.11.2026 · RAVEL-013 Touch**
ID: `user_27c011b47ee448`.
Хранение: `results/analysis_profiles.json`. Доступен для любого проекта.

Основные параметры:
- RAVEL-VB-013-9f (ONNX CUDA, GPU 0, VRAM arena без лимита);
- VballNetV4c (ONNX CUDA, confidence 0.50);
- RAVEL Touch action threshold **0.70** (значение из примера upstream);
- новый поиск пиков Touch для диагностического MP4: smoothing 5 кадров, min gap 10 кадров, подсветка игрока 6 кадров, лента ±4 секунды;
- пропуск кадров RAVEL 1 (проверять каждый кадр), stride 9;
- декодирование RAVEL: новый FFmpeg YUV reader, CPU decoder, auto threads, без NVDEC для совместимости;
- генерация `players-annotated.mp4` с лентой Touch, отметкой исполнителя, рамками игроков; сохранение полных raw proposals для CPU replay;
- дополнительные векторы ReID отключены, чтобы уменьшить расход диска; модуль распознавания номеров игроков не подключён автоматически.

**Важно:** новый peak picking upstream используется только при генерации диагностического видео. CPU-постобработка касаний и классификация розыгрышей в Volley Studio остаются отдельной стадией. Она использует обновлённый `src/player_contacts.py`, но не заменяет всё на `find_touch_events`.

## Как сравнить

1. Откройте проект `new` через цепочку в шапке; во вкладке «Анализ» выберите **один и тот же контрольный отрезок 30–90 секунд**, где видны несколько подач, передач и спорных касаний. Текущее видео проекта длится ~51 мин.
2. Выберите профиль `Новый` для контрольного запуска (по желанию, чтобы сохранить baseline). Запустите полный анализ фрагмента, дождитесь сохранения результатов.
3. Не меняя диапазон, выберите **Upstream 04.11.2026 · RAVEL-013 Touch** и снова запустите анализ. Новая ветка не перезаписывает предыдущую.
4. В шапке переключайте «Первичный анализ» между двумя запусками; в «Предпросмотре» сравнивайте таймлайн, рамки и модельные касания. Для «Касания RAVEL-013 · без эвристик» полезно установить порог **0.70**.
5. В новой ветке появляется кнопка **«Скачать Touch MP4 · upstream»** рядом с названием видео: это оригинальная диагностическая лента peak picking, которую можно открыть в локальном видеоплеере. Доступ к MP4 ограничен выбранной веткой через `cache_id`.
6. При необходимости создайте отдельную версию CPU-постобработки в «Предпросмотре» (RAVEL Touch или гибрид VballNet+RAVEL). Только после этого сравнивайте количество событий и границы розыгрышей; другие версии сохраняются.

## Как оценить

На одном и том же диапазоне вручную отметьте касания и начала/концы розыгрышей. Сравните количество пропусков, ложных Touch и неправильных границ, а также длительность GPU/CPU-стадий. Рост числа меток сам по себе не означает повышение точности.

## Ограничения

- Новая RAVEL-013 ONNX-модель уже была в форке; latest upstream изменил **обработку и визуализацию**, а не заменил ONNX-веса на новую модель.
- Диагностический MP4 записывается в `MPEG-4 Part 2` текущей реализацией upstream, поэтому браузер может не воспроизвести его напрямую; файл скачивается для VLC/локального плеера.
- На HOME-PC 04.11.2026 было свободно около **11 ГБ** на C:. Не запускайте диагностику целого 51-минутного видео без проверки свободного места.
- Новый FFmpeg YUV + ONNX CUDA проверены на коротком синтетическом видео: кэш и MP4 создаются. Качество касаний на реальном матче не измерено.
- Поддержка ReID, распознавания номеров и Celery upstream пока не подключена к основному интерфейсу Volley Studio; один профиль не включает эти независимые пайплайны.

Файлы конфигурации и интеграции: `scripts/volleyball_studio/advanced.py`, `scripts/volleyball_studio/analysis.py`, `scripts/volleyball_ui/static/index.html`, `scripts/volleyball_ui/server.py` и `scripts/volleyball_ui/static/results-ui.js`.
