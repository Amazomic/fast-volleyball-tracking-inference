# Управление монтажом на русском

Вызовите `$volleyball-reels-studio` и опишите результат свободным текстом. Агент извлекает условия и передаёт их CLI; неясные важные условия уточняет, остальное берёт по умолчанию. Локальный CLI дополнительно поддерживает распространённые русские формулировки через `--request`; его детерминированный парсер не заменяет полноценное языковое понимание агента.

```bash
PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --request "Сделай ролик на 30 секунд, только атаки, динамичный монтаж, с музыкой"
```

Для проверки извлечённых параметров без обработки видео добавьте `--plan-only`. Явные CLI-параметры имеют приоритет над распознанными из текста.

Поддерживаются «только атаки», «только блоки», «лучшие подачи», «длинные розыгрыши», их сочетания, числовая и распространённая словесная длительность, число роликов, стили, эффекты и базовые требования к звуку. Несколько типов событий образуют объединение; условие длинного розыгрыша дополнительно ограничивает источник эпизода. Длинным по умолчанию считается розыгрыш от 10 секунд, дополнительный минимум задаётся фразой «не короче 15 секунд» или `--min-rally`.

Тематический фильтр: `--events attack block serve`, порог `--event-confidence 0.75`. Отбираются только достаточно уверенные события. Без геометрии block/serve не подтверждаются и не используются в тематическом монтаже. Атаки не заменяются передачами или случайными розыгрышами при недостатке материала. Для каждого выбранного события создаётся короткий участок с контекстом вокруг контакта.

«Ролик на 30 секунд» означает один итоговый монтаж из нескольких эпизодов. `--count` задаёт число готовых монтажей. Конвейер выбирает порядок, длину участков, ретайминг, движение перехода и звук. Длительность является целевой верхней границей; при недостатке подтверждённых событий допустим более короткий результат с предупреждением вместо случайного заполнения. Важное действие сохраняется в пределах доступного контекста.

По умолчанию используется бюджет **8 CPU**: `--threads 8`, ограничение affinity процесса и наследующих дочерних процессов, ограничения библиотечных thread pools. На машине с меньшим числом доступных CPU используются доступные. Это общий бюджет CPU, а не 8 процессов монтажа. GPU для распознавания/кодирования может использоваться отдельно. Переопределение — `--threads`.

Планировщик учитывает фактический ретайминг перед экспортом. Если последний эпизод не помещается вместе с доступным контекстом контакта, он может быть пропущен вместо обрыва важного действия; недостаток длительности отражается в отчёте.

Видеопереходы не используют затемнение. Для Dynamic/Cinematic остаётся плавный zoom длительностью около 0.4 с на границе. Короткие звуковые fade сохранены для устранения щелчков. Огонь после уверенной атаки может длиться до 1 с, контактная вспышка — около 0.27 с, shake — около 0.3 с; шлейф хранит до 18 кадров. Свечение, толщина и размеры увеличены. Все объектные эффекты прекращаются при потере уверенного мяча и подчиняются защите перекрытий. В режиме off художественные эффекты выключены.
