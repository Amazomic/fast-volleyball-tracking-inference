# Volley Studio — работа с проектами

Локальный адрес: http://127.0.0.1:8765

Запуск в Windows: `start-volley-ui.cmd`; в WSL из корня репозитория:
`.venv/bin/python -m scripts.volleyball_ui`.

## Порядок работы

1. **Создать проект:** кнопка справа в шапке. Введите уникальное название
   (по умолчанию сегодняшняя дата) и отметьте видео из `project/`.
   Список доступных файлов сканируется только при открытии этого окна.
   Если название уже используется, сервер отклоняет создание и переименование.
2. **Анализ:** настройте модель ONNX/OpenVINO, размер кадра, пороги, потоки,
   профиль пляжного волейбола. Для каждой записи доступен предпросмотр,
   шкала игровых событий и отдельные временные границы. Кнопка «Запустить»
   анализирует видео проекта последовательно и сохраняет результаты в этот проект.
3. **Игроки:** выбирайте записи проекта, просматривайте фотографии track ID,
   присваивайте имена и объединяйте идентификаторы одного спортсмена.
4. **Отчёт:** общие показатели проекта, суммирование по источникам.
5. **Бенчмарк:** реальный замер обработки отдельного видео проекта.
6. **Монтаж:** сборка лучших полных розыгрышей из всех видео проекта.

Создание проекта само по себе **не запускает анализ**.

## Вкладка «Бенчмарк»

Выберите исходное видео, начальную секунду, длину короткого участка (5/15/30/60 с),
ширину кадра и CPU-потоки.

- **Декодирование и масштабирование (FFmpeg):** замер количества реально
  декодированных кадров в секунду. Не включает нейросети.
- **Полный анализ:** отдельный свежий прогон нейросетей и других стадий
  на коротком отрезке. Включает и время загрузки моделей, поэтому итоговый FPS
  — это средняя производительность **всей цепочки**, а не FPS отдельной модели.

Показываются средняя скорость (FPS), реальное время выполнения (с) и
коэффициент относительно воспроизведения 1×. Результаты хранятся в
`results/projects/<project-id>/benchmarks/history.json`, подробные журналы —
в `benchmarks/runs/<run-id>/execution.log`. Бенчмарк не изменяет результаты
основного анализа, не использует его кэш и может быть остановлен.

## Устройство хранения

```text
project/                                     # исходные видео, не меняются
results/
  projects/
    projects.json                            # список проектов (ID, название, видео)
    <project-id>/
      project.json                           # настройки конкретного проекта
      analysis/                              # новые результаты инференса
      runs/                                  # выходные артефакты анализа
      reports/summary.json                   # отчёт по проекту
      reports/<video>.player_statistics.json # статистика конкретного исходника
      player_identities.json                 # имена/привязки track ID
      player_photos/                          # картинки игроков и индексы
      logs/                                  # выполнение задач
      benchmarks/                            # история и журналы замеров
      highlights.mp4                         # общий итоговый ролик
      highlights_manifest.json              # исходники выбранных розыгрышей
```

Имена проектов сравниваются после нормализации пробелов и регистра.
Старые дубликаты имён (если есть) мигрируются с суффиксом `(2)` и сохранением ID.

**Исторический кэш:** для старых проектов разрешено явно закреплённое
`legacy_analysis.json` с указанием на ранее рассчитанный общий кэш
`results/analysis/<id>/`. Это позволяет не копировать многогигабайтные
результаты и не терять ранее выполненный анализ. Такой кэш используется
только для чтения; новые вычисления и прочие данные сохраняются изолированно
в каталог выбранного проекта.

Все результаты в `results/`, исходные записи в `project/`, локальные среды,
логи, кэши инструментов и временные файлы исключены из Git посредством
`.gitignore`. Уже отслеживаемые в исходном репозитории демонстрационные
видео и модели не удалялись.

## Проверка

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_volleyball_ui*.py' -v
```

Сервер доступен только на localhost. Не открывайте его напрямую в интернет.
