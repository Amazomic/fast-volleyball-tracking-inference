# Volley Studio — проекты, анализ и просмотр розыгрышей

Локальный адрес: http://127.0.0.1:8765

Запуск Windows: `start-volley-ui.cmd`; WSL: `.venv/bin/python -m scripts.volleyball_ui`.

## Последовательность работы

1. **Создать проект.** Название (по умолчанию дата) и выбор одного или нескольких видео из `project/`.
   Доступные файлы ищутся только при открытии окна создания/редактирования.
   Исходники остаются на месте. Одинаковые названия проектов запрещены.
2. **Анализ.** Один общий блок «Видео и диапазон анализа»: большое видео слева,
   добавленные записи проекта справа и шкала времени внизу внутри той же панели.
   Ниже расположен отдельный блок параметров запуска.
   Под горизонтальным разделителем располагается одна общая шкала на всю
   ширину панели: белый маркер перематывает видео, зелёные маркеры задают
   начало и конец анализа. Под шкалой остаются только два числовых поля
   границ начала и конца (в секундах) с автоматическим сохранением.
   Перетаскивание границ сразу обновляет значения полей, ввод секунд —
   перемещает зелёные маркеры. Воспроизведение и звук находятся
   непосредственно на видеоплеере; клавиши Пробел и стрелки управляют просмотром.
   Для каждой записи диапазон сохраняется отдельно.
   Ниже, в отдельной панели, расположены параметры запуска: ONNX Runtime/OpenVINO,
   автоматическая либо ручная целевая ширина, потоки CPU и профиль
   пляжного волейбола. Порог отбора и минимум розыгрыша задаются в «Монтаже». Никаких обнаруженных событий,
   розыгрышей и статистики на этой вкладке нет.
   Для каждой записи диапазон сохраняется отдельно. Кнопка «Запустить анализ»
   обрабатывает все видео проекта последовательно. Предпросмотр исходного видео
   не зависит от наличия результатов анализа или ранее созданных копий.
3. **Результат анализа.** Видео из результатов текущего проекта с графической
   разметкой по времени обнаруженных игровых событий. При событиях выводятся
   тип действия и track ID игрока (если определён), а также маркер мяча
   в сохранённых координатах контакта. Справа пронумерованные обнаруженные
   розыгрыши. Щелчок по номеру переносит на начало эпизода и запускает
   **только его интервал**; на достижении конца воспроизведение останавливается.
   Ниже проигрывателя — обзорная шкала с блоками розыгрышей и метками действий.
   Внизу находится журнал выполнения анализа.
4. **Игроки.** Для каждой записи отдельно можно изучить фото track ID и
   объединить повторные ID под одним именем.
5. **Отчёт.** Сводная статистика всех проанализированных записей.
6. **Бенчмарк.** Короткий замер скорости декодирования FFmpeg или всей цепочки
   анализа, история по проекту.
7. **Монтаж.** Общий ролик из наиболее зрелищных полных розыгрышей проекта.

Границы розыгрышей и типы событий определяются алгоритмами приближённо.
Отсутствие события не означает, что его не было. Графическая разметка поверх
видео в текущей версии показывает **обнаруженные действия/контакты**, а не
непрерывные bounding box всех игроков на каждом кадре.

## Форматы видео и быстрый просмотр

**Предварительно перекодировать видео не нужно.** Положите исходный файл
в `project/`, создайте проект и выберите запись. Видео можно смотреть без
запуска анализа и без восстановления файлов предыдущего проекта.

- Совместимый с браузером MP4/H.264 передаётся из оригинального файла.
- HEVC/H.265 и другие кодеки, читаемые FFmpeg, но несовместимые с браузером,
  просматриваются через небольшие H.264-фрагменты **по 18 секунд**.
  Запрашивается только нужное место; перемотка не обрабатывает весь матч.
  При непрерывном просмотре следующий фрагмент подгружается автоматически.
- Оригинал остаётся неизменным. В совместимый формат переводится только
  нужный участок, а **полного предварительного перекодирования нет**.
- Короткие временные клипы сохраняются в `results/ui_stream/` и переиспользуются
  между проектами; общий объём кэша ограничен **160 МБ**.

Исходный контейнер и кодек должны поддерживаться локальной сборкой FFmpeg.
Это не требование к ручной перекодировке: для большинства обычных записей
всё происходит автоматически при просмотре.

## Хранение

- `project/` — входные файлы.
- `results/projects/projects.json` — реестр проектов.
- `results/projects/<project-id>/project.json` — видео и диапазоны.
- `results/projects/<project-id>/analysis/` — новые вычисления.
- `results/projects/<project-id>/reports/` — отчёт.
- `results/projects/<project-id>/player_identities.json` — имена игроков.
- `results/projects/<project-id>/logs/` — журнал выполнения.
- `results/projects/<project-id>/benchmarks/` — замеры.
- `results/projects/<project-id>/highlights.mp4` — монтаж.

Старым проектам может быть закреплён исторический кэш общего анализа для чтения,
без копирования исходного видео. Новые данные генерируются отдельно по проектам.
Git исключает локальные видео, кэши, временные файлы и результаты.

Сервер работает только на localhost. Не публикуйте его напрямую в интернет.

## Разметка площадки до анализа

На вкладке **Анализ** выберите конкретное видео и подходящий кадр. Над видео нажмите **Разметить площадку**. На изображении последовательно поставьте восемь опорных точек:

1. Ближний левый угол площадки
2. Дальний левый угол
3. Дальний правый угол
4. Ближний правый угол
5. Условная середина боковой линии слева
6. Условная середина боковой линии справа
7. Левая точка сетки
8. Правая точка сетки

Для пляжного волейбола точки 5–6 не обозначают существующую разметочную линию атаки; это условные ориентиры. Готовые точки можно перетаскивать, последнюю — отменить, всю разметку — сбросить.

**Сохранить диапазон и разметку** записывает выбранные начало/конец и восемь состояний точек. Координаты сохраняются только для наблюдаемых или оценочных ориентиров. Ниже, в блоке **Настройки запуска анализа**, находится таблица по каждому видео: сохранённый временной отрезок и наличие разметки площадки. Разметка проекта хранится в `results/projects/<project-id>/courts/<filename>_court.json`.

При запуске анализа каждому видео явно передаётся **его проектный** `--court-json`. При отсутствии разметки передаётся `--no-court-fallback`: алгоритм не использует чужой файл или случайную глобальную разметку. Существующая разметка по умолчанию не копируется между проектами. Изменение разметки приводит к повторному вычислению стадий, которые зависят от геометрии, даже если распознавание мяча/игроков ранее было закэшировано.

**Ограничение:** один набор из восьми точек применяется ко всей выбранной записи. Для видео с движущейся камерой потребуется будущая покадровая/сегментная калибровка; текущий интерфейс не делает её автоматически. Не сохраняйте разметку другого ракурса.


## Универсальная разметка и отображение видео

Вкладка **Анализ** показывает исходное видео в его настоящей ориентации:
вертикальное видео остаётся вертикальным, горизонтальное — горизонтальным.
Плеер не растягивается до широкого прямоугольника с чёрными полосами.
Единая шкала времени имеет точно такую же ширину, как плеер.
Размытый фон при сборке Reels — отдельная монтажная функция, а не анализ.

Разметка площадки **необязательна**. По умолчанию редактор выключен;
анализ может запускаться и без неё. Геометрически зависимые события
в таком случае могут определяться хуже или не определяться.

Для разметки нажмите **«Разметить площадку»** над видео. Изображение
уменьшится, освободив место вокруг кадра. Далее просто щёлкайте по очереди
восемь точек. При щелчке внутри кадра сохраняются статус *visible* и
координаты кадра; за границей — статус *estimated* и реальные координаты,
возможно отрицательные. Предполагаемые точки показываются оранжевым.
Если положение неизвестно, нажмите **«Пропустить точку»**, чтобы записать
статус *unknown* и отсутствие координат. Можно отметить часть точек:
оставшиеся при сохранении будут обозначены как неизвестные.

«↶ Назад» отменяет последнее действие, «Сбросить» очищает черновик,
«Завершить разметку» выключает редактор. Ранее поставленные точки
можно передвигать; при повторном редактировании точки выбираются по порядку.
Кнопка **«Сохранить диапазон и разметку»** сохраняет и временной диапазон,
и статусы точек отдельно для каждого видео проекта.

При неизвестном угле матрица перспективы не создаётся, так как нельзя
использовать неизвестные координаты. Предполагаемый угол за кадром позволяет
строить перспективу, но она может быть неточной. Если камера движется,
одной статической разметки может быть недостаточно.


## Настройки выбранного проекта

Шестерёнка справа от центрального выпадающего списка в шапке открывает две команды:

- **Переименовать проект**: ввод нового уникального имени, без повторного сканирования исходной папки и без изменения видео/результатов.
- **Удалить проект**: только после отдельного подтверждения. Проект исключается из списка, его метаданные и локальные результаты переносятся в `results/projects/.trash/<project-id>/`. Исходные видео из `project/` и общий исторический кэш остаются неизменными. Запущенный анализ текущего проекта блокирует операцию. Результаты при необходимости можно восстановить из архива вручную.

## Галерея и шкала на вкладке «Анализ»

Над горизонтальной линией находятся просмотр видео (с сохранением исходной
ориентации) и **прокручиваемый список видео проекта** справа.
Высота верхней области на настольном экране фиксируется относительно высоты окна,
поэтому вертикальное видео не меняет расположение расположенных ниже элементов.
Под разделительной линией **одна шкала и два поля с секундами** занимают
всю ширину панели, независимо от ориентации видео. Зелёные маркеры и поля
синхронизируются в обе стороны; сохранение выполняется отдельной компактной
кнопкой. Воспроизведение/звук — на самом видео. На узком экране список файлов
находится под проигрывателем, а шкала — ниже списка на полную ширину блока.

Интерфейс отображается в масштабе 80%. Центральный список проектов и шестерёнка
уменьшены дополнительно примерно вдвое, включая высоту, ширину и размеры шрифтов.


## Компактная шапка видеоплеера и крайние точки шкалы

В верхней строке панели анализа:
- Слева только надпись «Видео для анализа» и раскрываемый значок **!**,
  объясняющий, как исходное видео воспроизводится в браузере без подготовки полной копии.
- По центру — одна кнопка **«Разметить площадку · необязательно»**.
  При редактировании в этой же кнопке отображается прогресс точек.
- Справа — краткие параметры текущего исходника.

Список видео проекта справа остаётся доступен для переключения файлов,
однако заголовок и кнопка изменения состава проекта внутри анализа убраны.

На шкале зелёные линии начала и конца математически совпадают с крайними
границами дорожки, включая 0% и 100%. Лишняя граница заливки удалена;
крайние захваты остаются внутри визуального фона.


## Неподвижная строка и разметка на всей площади просмотра

Строка над плеером («Видео для анализа» · «Разметить площадку» · имя/размер/длительность)
имеет фиксированные размеры и расположение при включении/выключении разметки.
Дополнительные команды «Пропустить точку», «Назад» и «Сбросить» располагаются
поверх рабочей области и не перестраивают интерфейс.

Видеоплеер занимает **неизменную по размеру область левой колонки** независимо от
режима. Само исходное вертикальное видео остаётся вертикальным и центрируется
в поле; в режиме разметки его отображение уменьшается до 84% прежнего.
Вся свободная площадь вокруг изображения используется для установки
предполагаемых закадровых точек. Координаты вычисляются по фактическому
размеру изображения, а не по габаритам широкой колонки; точки за кадром
имеют статус estimated и могут получать отрицательные координаты.
Сервер валидирует расширенные координаты, но по-прежнему отвергает
экстремальные значения и неизвестные точки без надлежащего статуса.
Шкала времени и список записей не изменяют размеры при переключении.

## Автосохранение и быстрый сброс контекста

Под временной шкалой — два компактных числовых поля **без видимых подписей**
(для клавиатуры/скринридеров доступны названия начала и конца анализа).
Изменение значений и перемещение зелёных границ автоматически сохраняется
в проект через короткую задержку после редактирования, без кнопки
«Сохранить» и без текста «Сохранено» в обычном состоянии.
При ошибке показывается компактное сообщение рядом с полями.
Перед переключением видео или запуском анализа ожидается завершение записи,
чтобы не потерять последние изменения.

Разметка площадки сохраняется автоматически по мере постановки,
пропуска, отмены и перемещения точек. Автосохранение не закрывает
редактор и не сбрасывает историю. Данные сохраняются отдельно по видео
внутри проекта.

В блоке **«Сохранённый контекст по видео»** у каждой записи справа
есть кнопка **×**. Нажатие без подтверждения сбрасывает только эту
запись: возвращает полный диапазон времени и удаляет файл разметки
её площадки. Данные остальных записей проекта и исходное видео
не затрагиваются.

Шаги для отступов и размеров: 5 / 8 / 13 / 21 px (приближение
пропорций золотого сечения). Текст кнопки разметки и статус
расположены двумя симметричными строками по центру фиксированной кнопки.


## Разделение настроек анализа и монтажа

Во вкладке **«Анализ»** остаются только параметры вычислений:
движок обнаружения мяча (ONNX Runtime/OpenVINO), автоматическая/ручная
ширина кадра, CPU-потоки, тип площадки (пляжный волейбол).
Временной интервал и разметка сохраняются отдельно для каждого исходного
видео. Параметры монтажа не отправляются в задачу анализа.

Во вкладке **«Монтаж»** находятся:
- Желаемая длительность итогового ролика.
- **Минимум розыгрыша, с** — порог реальной продолжительности
  обнаруженного эпизода, без добавляемых монтажных полей.
- **Минимальная уверенность розыгрыша** — отбор только эпизодов,
  у которых эвристическая уверенность не ниже заданного значения;
  это **не порог нейросети обнаружения мяча**.

Анализ сохраняет широкий рейтинг кандидатов с низким предварительным
порогом, а монтаж фильтрует их без повторного запуска нейросетей.
Первичный расчёт треков допускает эпизоды от 0,5 секунды; отбор для
финального ролика происходит позже. Для проектов, рассчитанных старой
версией (которая сохраняла только заранее отфильтрованный ranking.json),
необходимо **один раз повторно запустить «Анализ»** для расширения рейтинга.
При наличии кэша нейросетевые предсказания переиспользуются; короткие
треки и рейтинг будут пересчитаны. Удалять существующие результаты не нужно.

В манифесте ролика results/projects/<project-id>/highlights_manifest.json
сохраняются применённые пороги монтажа, что позволяет видеть условия отбора.

## Ход анализа, рабочая шкала и использование CPU/GPU

После нажатия «Запустить анализ» интерфейс остаётся во вкладке
**«Анализ»** и прокручивается к блоку **«Ход обработки»**.
Там находятся журнал, текущий этап, кадры, скорость FPS и кнопка
остановки. Блок «Результат анализа» не показывает пустое видео,
пока обработка не закончена; в нём появляется информационная карточка.

Шкала содержит **один перетаскиваемый белый маркер** текущего положения.
Два значения времени расположены на кнопках **«Начало»** и **«Конец»**.
Нажатие соответствующей кнопки задаёт границу равной текущему
положению, синхронизирует выделенный диапазон и запускает
автосохранение. Отдельных перетаскиваемых границ или текстовых
полей секунд нет.

В списке движков явно различаются:
- **ONNX Runtime — CUDA (GPU)**: поиск мяча на видеокарте, CPU fallback
  для отдельных операций, недоступная CUDA вызывает ошибку.
- **ONNX Runtime — CPU**: поиск мяча только на CPU;
  число потоков устанавливается через SessionOptions.intra_op_num_threads.
- **OpenVINO — CPU**: альтернативный движок для мяча; игроки в любом
  случае определяются через OpenVINO CPU.

Число потоков применяется к CPU-подготовке видео FFmpeg и распознаванию
игроков OpenVINO; в CPU-режиме ONNX — также к поиску мяча.
Это не обещание полной загрузки указанного числа логических ядер:
потоки — максимум параллелизма, производительность зависит от этапа.

Нельзя перезапускать локальный сервер посреди активного анализа: задача
работает в дочернем процессе, а текущий сервер хранит ссылку на неё
в памяти. Обновлять статические HTML/JS/CSS безопасно; новые серверные
параметры применяются после штатного перезапуска между анализами.


## Контекстные CPU-потоки и прокрутка журнала

Поле **«Потоки CPU»** отображается в форме запуска анализа только
при выборе **«ONNX Runtime — CPU»** или **«OpenVINO — CPU»**.
Для **«ONNX Runtime — CUDA (GPU)»** оно скрыто и отключено, поэтому
не попадает в запрос запуска; сервер применяет стандартную настройку
для вспомогательных CPU-этапов. Введённое значение сохраняется при
переключении между движками без изменения уже запущенного анализа.

Журнал блока **«Ход обработки»** имеет ограниченную высоту и собственную
вертикальную полосу прокрутки. При нахождении внизу он автоматически
следует за новыми строками; если пользователь прокрутил вверх для чтения
истории, положение не сбрасывается при обновлении журнала.
