# Volley Studio — веб-интерфейс

Локальная веб-панель для видеоанализа, ручного объединения ID игроков, просмотра статистики и монтажа.

## Запуск на Windows + WSL (Ubuntu-25.04)

**Самый простой вариант:** дважды нажать на `start-volley-ui.cmd` в корне репозитория. Откроется браузер на <http://127.0.0.1:8765>.

Из терминала WSL в корне репозитория:

```bash
.venv/bin/python -m scripts.volleyball_ui
```

Нужны уже подготовленное окружение `.venv`, `ffmpeg` и существующие модели проекта.
Для самого веб-сервера дополнительных Python-пакетов не нужно: он использует стандартную библиотеку.

## Разделы

- **Обзор:** выбор исходного видео из `project/`, количество найденных игровых эпизодов, действий и ID, ссылки на результаты.
- **Анализ:** выбор видео, backend (ONNX/OpenVINO), ширина обработки, порог уверенности, минимальная продолжительность эпизода, начало/длительность обработки, число потоков, пляжный волейбол. Запуск, статус и остановка из браузера.
- **Игроки и ID:** фотографии игрока рядом с каждым track ID, просмотр трёх кадров одного ID, выбор нескольких ID, назначение имени, перенос между группами, удаление привязок. Объединённая статистика по выбранным ID.
- **Отчёт:** эвристические игровые события и суммы действий именованных игроков.
- **Готовые ролики:** сборка ~2-минутных подборок из полных распознанных розыгрышей и просмотр MP4 через HTML5.

## Где лежат данные

- `project/*.mp4` — исходные видео (не изменяются).
- `results/analysis/<id>/` — сохранённые inference-результаты (доступны повторно).
- `results/player_identities.json` — **ручные привязки** имён к ID, отдельно от исходных результатов распознавания.
- `results/ui_runs/*.log` — журналы задач, запущенных через UI.
- `results/ui_runs/<run-id>/` — служебные отчёты выполнения.
- `results/highlights_120s.mp4`, `results/highlights_manifest.json`, `results/player_statistics.csv` — нарезки и статистика.

При пересчёте уже обработанного исходника используются кэшированные стадии, если их ключи и контрольные суммы совпадают. При изменении настроек некоторых стадий повторный inference возможен.

## Фотографии по track ID

Во вкладке **Игроки и ID** рядом с каждым ID показана миниатюра из исходного анализа. Нажатие на неё открывает справа до трёх кадров этого же трека в разные моменты времени. Каждый кадр можно открыть отдельно в увеличенном размере.

При выборе нескольких ID галерея показывает их фотографии друг под другом для визуального сравнения (до шести ID одновременно, остальные продолжают учитываться при сохранении).

Фотографии берутся из bounding box детекций в `results/analysis/<cache-id>/players.json` и кадров `analysis.mp4`; нейросети не запускаются повторно. Генерация **по запросу**; кэш JPEG и индекс кадров находятся в `results/player_photos/<cache-id>/`. При обновлении `players.json` миниатюры пересоздаются. Одно изображение не подтверждает личность — сравнивайте все доступные кадры.

## Объединение ID

1. Открыть вкладку **Игроки и ID**.
2. В таблице выбрать, например, ID 725 и 1266.
3. Ввести имя спортсмена и нажать **Сохранить и объединить**.
4. Если трекер позже обнаружил нового ID этого человека, выбрать новый ID и указать **то же имя**.

Приложение суммирует детектированные действия. Оно **не исправляет** нейросетевой tracker автоматически и не гарантирует, что два ID действительно принадлежат одному спортсмену. Неизвестные ID остаются отдельными.

## Ограничения первой версии

- Это **локальный** интерфейс без системы авторизации; сервер слушает только `127.0.0.1`. Не открывайте его напрямую в интернет.
- Видео выбираются из папки `project/` на компьютере, загрузка из браузера пока не реализована.
- Источником для отображаемого отчёта являются сохранённые события. Без разметки площадки подачи/блоки не являются надёжными метками, а начало и конец розыгрыша лишь приблизительны.
- В `player_statistics.csv` находятся статистики треков; объединённые имена и агрегаты доступны через UI и `results/player_identities.json`.
- История задач сохраняет логи, но восстановление контроля над уже запущенным процессом после перезапуска самого сервера не реализовано.
- Полноценный интерактивный редактор границ и корта — отдельная следующая итерация.

## Проекты и несколько исходных видео

1. Откройте вкладку **Обзор**, введите название и нажмите **Создать проект**.
2. Отметьте исходные файлы из папки project/ и нажмите **Сохранить видео проекта**.
3. В **Анализ видео** выберите каждый файл в верхнем списке и выставьте границы нужного участка; файлы без ручного выбора будут обработаны полностью.
4. Запустите анализ. Все файлы выбранного проекта анализируются последовательно. Если параметры и исходные данные не изменились, используется кэш.
5. В **Готовые ролики** выберите длительность и создайте общий ролик. Самые зрелищные розыгрыши выбираются из всех видео проекта; целые эпизоды не укорачиваются ради точной длительности.

Пути: results/projects/projects.json — список проектов; results/projects/<project-id>/highlights.mp4 — итоговый ролик; results/projects/<project-id>/highlights_manifest.json — события по источникам. Исходные записи не копируются и не изменяются.

## Предпросмотр и шкала анализа

Автоматическая ширина — не выше 1280 px и не больше ширины исходного кадра после применения поворота. Высота рассчитывается пропорционально. Ручная настройка доступна в дополнительных параметрах.

Слева на предпросмотре исходный кадр; справа — тот же кадр с целевым размером для анализа. Временная шкала показывает:
- зелёные блоки — обнаруженные розыгрыши, границы приблизительные;
- оранжевые метки — атаки, фиолетовые — блоки, бирюзовые — подачи;
- жёлтые метки — приёмы, синие — верхние передачи;
- две зелёные границы — начало и конец выбранного диапазона, белая линия — просматриваемый кадр.

Клик по метке открывает соответствующий кадр. Границы диапазона перетаскиваются мышью или задаются числом в секундах. Каждое видео проекта имеет собственный диапазон. Метки берутся из сохранённых результатов событий, а не рассчитываются заново.


Имена игроков теперь привязываются к идентификаторам внутри выбранного проекта: results/projects/<project-id>/player_identities.json. Для каждого исходного видео track ID имеет собственную область значений, а в итоговом отчёте одно и то же заданное человеком имя объединяется между записями проекта.
