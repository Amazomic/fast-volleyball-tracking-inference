# Volley Studio — проекты, анализ и просмотр розыгрышей

Локальный адрес: http://127.0.0.1:8765

Запуск Windows: `start-volley-ui.cmd`; WSL: `.venv/bin/python -m scripts.volleyball_ui`.

## Последовательность работы

1. **Создать проект.** Название (по умолчанию дата) и выбор одного или нескольких видео из `project/`.
   Доступные файлы ищутся только при открытии окна создания/редактирования.
   Исходники остаются на месте. Одинаковые названия проектов запрещены.
2. **Анализ.** Большое видео слева, добавленные в проект записи — справа.
   Под проигрывателем шкала для выбора начала и конца обрабатываемого участка.
   Под шкалой — исключительно параметры запуска: ONNX Runtime/OpenVINO,
   автоматическая либо ручная целевая ширина, порог детекции, минимальный розыгрыш,
   потоки CPU и профиль пляжного волейбола. Никаких обнаруженных событий,
   розыгрышей и статистики на этой вкладке нет.
   Для каждой записи диапазон сохраняется отдельно. Кнопка «Запустить анализ»
   обрабатывает все видео проекта последовательно. Если существует полная совместимая
   H.264-копия из предыдущего анализа, она может использоваться для просмотра
   исходной записи в браузере без отображения поверх неё результатов.
3. **Результат анализа.** Видео из результатов текущего проекта с графической
   разметкой по времени обнаруженных игровых событий. При событиях выводятся
   тип действия и track ID игрока (если определён), а также маркер мяча
   в сохранённых координатах контакта. Справа пронумерованные обнаруженные
   розыгрыши. Щелчок по номеру переносит на начало эпизода и запускает
   **только его интервал**; на достижении конца воспроизведение останавливается.
   Ниже проигрывателя — обзорная шкала с блоками розыгрышей и метками действий.
   Внизу находится журнал выполнения анализа.
4. **Игроки.** Для каждой записи отдельно можно изучить фото track ID и
   объединить повторные ID под одним именем.
5. **Отчёт.** Сводная статистика всех проанализированных записей.
6. **Бенчмарк.** Короткий замер скорости декодирования FFmpeg или всей цепочки
   анализа, история по проекту.
7. **Монтаж.** Общий ролик из наиболее зрелищных полных розыгрышей проекта.

Границы розыгрышей и типы событий определяются алгоритмами приближённо.
Отсутствие события не означает, что его не было. Графическая разметка поверх
видео в текущей версии показывает **обнаруженные действия/контакты**, а не
непрерывные bounding box всех игроков на каждом кадре.

## Хранение

- `project/` — входные файлы.
- `results/projects/projects.json` — реестр проектов.
- `results/projects/<project-id>/project.json` — видео и диапазоны.
- `results/projects/<project-id>/analysis/` — новые вычисления.
- `results/projects/<project-id>/reports/` — отчёт.
- `results/projects/<project-id>/player_identities.json` — имена игроков.
- `results/projects/<project-id>/logs/` — журнал выполнения.
- `results/projects/<project-id>/benchmarks/` — замеры.
- `results/projects/<project-id>/highlights.mp4` — монтаж.

Старым проектам может быть закреплён исторический кэш общего анализа для чтения,
без копирования исходного видео. Новые данные генерируются отдельно по проектам.
Git исключает локальные видео, кэши, временные файлы и результаты.

Сервер работает только на localhost. Не публикуйте его напрямую в интернет.
