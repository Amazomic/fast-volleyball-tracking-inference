# Цикл разработки Volley Studio

**Главная цель:** постоянно упрощать устройство приложения, измеримо повышая
качество итоговых событий и видео. Меньше кода само по себе не является
показателем успеха: регрессия распознавания или экспорта недопустима.

## От идеи до релиза

| Шаг | Результат | Стоп-условие |
| --- | --- | --- |
| 0. Постановка | Сценарий пользователя, симптом, ожидаемое поведение, затронутый контракт | Нет воспроизводимого результата |
| 1. Базовая линия | Текущий `master`, сохранённый вход, метрики/скриншоты, информация о запусках | Нет возможности сравнить до/после при изменении алгоритма |
| 2. Дизайн | 1 авторитетный владелец данных, какие файлы удаляются/обновляются, риск | Дублируется состояние или смешиваются GPU и CPU |
| 3. Тест | Падающий тест на дефект, регрессия на старый проект/формат, бюджет производительности | Изменение не наблюдаемо |
| 4. Реализация | Минимальный diff, локальные targeted tests, отсутствие правок live-кэша | Новый слой без необходимости |
| 5. Локальная проверка / PR | Результаты команд из [TESTING.md](TESTING.md), описание качества/отката | Тесты не пройдены или не запускались |
| 6. Ручная приёмка | UI на реальном видео; при алгоритмах — одинаковые размеченные фрагменты, до/после | Недоказанное качество золотого профиля |
| 7. Merge | Squash PR в `master`, локальные тесты и ревью подтверждены | Проверки или review не завершены |
| 8. Наблюдение | Проверить быстрый рилс, историю проекта, CPU replay, экспорт; вернуть изменение при регрессии | Потеря истории/качества |

## Правила архитектуры

Существующий контракт уже зафиксирован в
[ARCHITECTURE_INFERENCE_POSTPROCESSING.md](ARCHITECTURE_INFERENCE_POSTPROCESSING.md).
Не заводить второй источник правды. Изменение CPU-порогов, касаний, ReID,
интерполяции до трёх секунд и границ розыгрышей **не требует** нового GPU
инференса, пока нужные наблюдения сохранены. Исходный GPU-кэш неизменяем;
CPU-версии независимы. Сначала проверить ручное подтверждение идентичности;
вероятности ReID не считать калиброванными.

При реструктуризации:

- Удалять мёртвые маршруты, дубли и лишние состояния **после** теста на
  публичный сценарий. Не вводить абстракцию ради нескольких одинаковых строк.
- Сохранять совместимость старых проектов и форматов либо писать
  детерминированную миграцию с резервной копией и обратимым планом.
- Видеоподготовка общая и кешируемая; Quick Reel независим от проектов,
  но использует те же золотые CPU-настройки после собственного GPU запуска.
- Монтаж берёт исходный файл, а не прокси; проверять FPS, разрешение,
  аудио, таймкоды и наличие артефактов.
- Работающие фоновые задачи нельзя прерывать ради тестов или удаления
  не относящихся к ним результатов.

## Процедура PR

Создать ветку `fix/*`, `feat/*` или `refactor/*` от `master`.
PR небольшого размера: одна задача + соответствующие тесты и документация.
Не держать в одном PR переписывание Docker, UI и алгоритмов распознавания.
Использовать `.github/PULL_REQUEST_TEMPLATE.md`; ссылки на файлы и
фактические результаты обязательны.

GitHub Actions удалены: запуск cloud runner заблокирован биллингом.
Проверки теперь выполняются локально через `python -m scripts.ci.run_checks`
или `--full`, а фактические результаты прикладываются к PR.
Автоматической проверки перед слиянием **нет**. При необходимости можно
включить review и запретить force push без обязательных CI-статусов.

## Принятие улучшения

- **Функциональность:** сценарий от проекта до рилса работает для нового
  и старого проекта, перезагрузка и отмена безопасны.
- **Точность:** Touch precision/recall/F1, границы розыгрышей, ID switches
  и ошибочные объединения на **одних и тех же** ручных аннотациях. Сравнить
  текущий baseline и вариант; о ложных срабатываниях говорить отдельно.
- **Видео:** не ниже исходной ожидаемой частоты кадров и требуемого
  разрешения, корректный aspect ratio и синхронизация.
- **Производительность:** медленные запросы, задержка интерфейса,
  длительность CPU replay, повторный GPU inference и использование памяти.
- **Простота:** меньше точек истины и циклических связей, меньше дублирования,
  тесты проще, ответственность файлов объясняется одной фразой.

При конфликте выбирать **качество и устойчивость**, не сокращение LOC.
О любых ухудшениях сообщать явно; нельзя подтасовывать тестовые эталоны.
