# Независимый предпросмотр сырых данных GPU

## Задача

Реализовать во вкладке предпросмотра режим «Сырые», работающий напрямую с сохранёнными данными выбранного GPU-анализа. Для него не должна требоваться выбранная CPU-постобработка, и её наличие или результат не должны менять показ исходных обнаружений. Режим «Обработанные» продолжает показывать результат выбранной CPU-версии.

Визуально выделить переключатель «Обработанные / Сырые» как основное управление режимом отображения. В сыром режиме разместить три небольших отдельных блока настроек: VballNet, RAVEL и RTMPose-M. Каждый блок должен позволять независимо включать отображение данных модели и менять порог уверенности. Показывать данные и вероятности, действительно сохранённые соответствующей моделью; не придумывать отсутствующие обнаружения. Явно сообщать, когда для выбранного анализа данные модели отсутствуют.

VballNet показывает обнаружения мяча; RAVEL — свои сохранённые обнаружения мяча и игроков и доступные вероятности касаний; RTMPose-M — сохранённые точки и скелеты с порогом уверенности ключевых точек без привязки к CPU Track ID. Уточнить по реальной схеме, какие пороги нужны для отдельных видов данных RAVEL. Раздельно представлять сырые данные моделей и не смешивать их с CPU-касаниями. В обработанном режиме траектория мяча использует только VballNet.

## Что уже выяснено

- Текущий маршрут `/api/cpu/native/rallies/overlays` в `rust/volley-app/src/native_preview_overlay.rs` читает CPU replay и требует `rally_run_id`. Его нельзя считать независимым сырым предпросмотром.
- Исходный GPU fusion хранится в `native_gpu_fusions/<fusion_id>/frames.jsonl`; формат описан в `rust/volley-core/src/fusion.rs`, метаданные и проверка источника — в `rust/volley-app/src/inference_fusion.rs` и `rust/volley-app/src/cpu_retrack.rs`.
- Исходные RTMPose хранятся отдельно в `native_gpu_pose_runs`; проверка привязки к fusion, SHA и индекс находятся в `rust/volley-app/src/native_preview_pose.rs`. Существующий `enrich` сопоставляет позы с CPU-треками и не подходит для независимого показа.
- Интерфейс хранит выбор GPU в `s.analysis`; `setRuns`, `drawOverlay` и загрузка видео в `rust/volley-app/static/studio.js` сейчас связаны с `s.run`. При отсутствии CPU-версии нужно всё равно загрузить видео выбранного GPU-анализа и обеспечить просмотр его сырых данных.
- Частичный подготовительный шаг уже внесён в `native_preview_overlay.rs`: `raw_frame` принимает `player_candidates` из GPU fusion и прежнее поле `raw_player_candidates` из CPU replay. Тест `raw_fusion_players_are_not_dependent_on_cpu_replay` прошёл на Windows. Это ещё не маршрут и не делает текущий сырой режим независимым.
- В рабочем дереве много посторонних незакоммиченных изменений; сохранить их. Изменения подписи рамок и предыдущих вкладок предпросмотра тоже незакоммичены. Перед работой проверить `git status`, `git log`, карту владельцев и актуальный код.

## Реализация и проверки

1. Расширить существующего владельца предпросмотра отдельным серверным маршрутом для GPU-источника, с проверкой проекта, видео, fusion ID, манифеста, границ и SHA. Использовать ограниченное индексированное чтение; не изменять сохранённые доказательства и не создавать второй движок анализа.
2. Предоставить исходные точки RTMPose через существующий владелец pose без сопоставления с CPU-треками; сохранить проверку происхождения, SHA и границ, не интерполировать несуществующие результаты без явного обозначения.
3. Подключить сырой режим к выбранному GPU-анализу без `s.run`, включая загрузку видео и переходы между источниками; проверять ответы на соответствие выбранным проекту, видео и GPU-источнику и не показывать устаревшие кадры.
4. Построить три компактных блока и заметный переключатель режимов. Изменение порогов влияет только на представление сохранённых данных, без нового GPU-анализа и CPU-пересчёта.
5. Добавить содержательные тесты на работу без CPU-версии, независимые пороги моделей, исходные позы без треков, смену источника, отсутствующие модели и отказ при несовпадении SHA/происхождения. Проверить переключение режимов и реальное отображение в браузере, если доступны подходящие сохранённые данные.
6. Выполнить применимые проектные проверки из AGENTS.md, обновить `docs/RUST_MIGRATION.md`, отдельно сообщить о пропущенных GPU и real-match проверках. Не трогать пользовательские данные и активные задачи. Не перезапускать Studio во время анализа; HTML/CSS/JS в dev-режиме читаются с диска, Rust-маршрут требует пересборки и безопасного перезапуска.
