# Таблицы выбранного игрока

**Цель:** в просмотре выбранного игрока переключать две таблицы: привязанные ID текущего видео и сохранённые фотографии общей базы. Одновременно видна одна. Кнопка сохранения фотографий доступна рядом с переключателем.

**Подход:** использовать существующие привязки и альбомы, сохранить удаление фото с подтверждением внутри строки. Сохранение выбранного игрока ограничить текущим видео и запуском анализа; возвращать фактическое число новых фото и ошибки. Непроверенные автоматические привязки не должны становиться эталонами.

**Ограничения:** сохранить существующие незакоммиченные изменения, не добавлять комментарии в код, не коммитить. Пользователь подтвердил переключение таблиц и поручил приступить. Работа выполняется в текущем каталоге, поскольку он содержит необходимые незакоммиченные изменения.

## Риски для проверки

Смена игрока или видео во время сохранения не должна показывать результат в чужой карточке. Повторное сохранение не дублирует фото. Удалённые образцы не возвращаются. Автоматическая привязка без подтверждения не пополняет эталоны. Пустые таблицы имеют понятный текст.

## Результат

23 профильных Python-теста прошли, восемь JavaScript-проверок прошли. В браузере проверены табличный альбом реального игрока и взаимное исключение таблиц. Общий прогон: 526 тестов, 14 неуспешных проверок, 27 ошибок, один пропуск. Полный вывод сохранён в `output/player-tables-test.log`, список имён — в `output/player-tables-test-summary.json`. В окружении отсутствует pytest; использован unittest, поэтому часть модулей тестов не импортировалась.

Алгоритм трекера не изменён. Оценка и воспроизводимые сценарии находятся в `docs/player-id-continuity-audit.md`. Изменения не закоммичены.
