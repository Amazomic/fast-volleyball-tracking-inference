# Volley Studio — аудит архитектуры и UI (05.11.2026)

## Контракт данных

```
Проект (projects.py)
  ├─ исходные файлы / общая подготовка видео (prepared_videos.py)
  ├─ контекст проекта: диапазоны, разметка, выбранные игроки
  └─ первичный запуск анализа (run_project_analysis.py, analysis_runs.py)
       ├─ профиль глобальный; результат принадлежит проекту
       ├─ уникальный cache_id для каждого видео
       ├─ сохранённые предсказания GPU (inference.manifest.json)
       └─ одна или несколько независимых CPU-версий
            ├─ run_project_reprocess.py → volleyball_studio/reprocess.py
            ├─ postprocessing/<version_id>/postprocess.manifest.json
            ├─ треки, события, классификация и розыгрыши
            └─ использование в предпросмотре, игроках и монтаже
```

Сохранённая GPU-ветка не перезаписывается изменениями CPU-порогов. Неполная
CPU-версия не должна публиковаться в выборе запусков. Референсы игроков и
назначения Track ID относятся к реальному кэшу инференса, а не к случайному
варианту постобработки. Монтаж использует выбранную готовую версию событий,
но для экспорта должен брать оригинальное видео.

## Исправлено

- **`static/app.js`**: API-ответ с прежнего проекта/видео или более старого
  запроса списка анализов не может перетереть новый выбор; недопустим выбор
  ветки CPU от другого видео. Завершение анализа в другом проекте не
  переключает текущий. Результаты прежних анализов доступны даже при
  новом фоновом запуске GPU.
- **`run_project_reprocess.py`**: новая версия считается успешно созданной
  только после наличия корректного манифеста и файлов событий/рейтинга.
  Все видео проекта обязаны иметь одинаковые настройки CPU; пустой
  родительский запуск отклоняется.
- **`static/settings-tooltips.js` / `static/settings-tooltips.css`**:
  пояснения с действием и значением по умолчанию добавлены для параметров
  GPU/CPU, ReID, диагностики, бенчмарка и монтажа. Ссылочные
  `<label for>` тоже поддерживаются. Подсказки открываются над всей
  страницей, не обрезаются прокручиваемыми вкладками, доступны с клавиатуры.
- **`static/app.js`**: удалён пустой legacy-рендерер списка проектов.
- **`tests/ui_architecture_contract.cjs`**: контроль трёх уровней
  навигации, покрытие help-текстами технических полей и связность статических
  кнопок с JS-обработчиками/делегированными атрибутами.
- **`tests/test_postprocessing_version_selection.py`**: тестовый replay
  создаёт корректный манифест, добавлена проверка запрета публикации
  незавершённой CPU-версии.

## Сценарии для регрессии

1. F5/возврат на вкладку: сохранены проект, видеозапись и версия анализа.
2. Смена проекта во время ожидания API: старый ответ не перерисовывает новый.
3. Смена видео и первичного запуска: CPU-версии только его родительской ветки.
4. Смена CPU-версии: отчёт, список игроков и предпросмотр берут выбранный cache_id.
5. Завершение чужого анализа: текущий проект не переходит на чужую ветку.
6. Запуск новой нейросети: результаты предыдущего завершённого запуска
   доступны для просмотра до завершения нового.
7. Новые CPU-пороги: быстрый предпросмотр отдельно от сохранённой версии,
   публикация только после успешной обработки всех видео.
8. Игроки/ReID: подсказки не привязывают личность без подтверждения.
9. Подсказки: hover и keyboard focus в прокручиваемой секции, без обрезки.
10. Монтаж: выбор версии, ручное добавление эпизодов и просмотр рилса.

## Выполненные проверки

`node --test tests/*.cjs` — сценарии браузерного состояния (VM, без настоящего браузера).
`python -m unittest` — CPU replay, дерево зависимостей, версии.
`node --check` — синтаксис JS.
`git diff --check` — пробелы и конфликты редактирования.

**Ограничения:** полноценный интерактивный E2E в браузере и полный GPU
перезапуск не выполнялись во время пользовательского анализа. Изменения
server-side Python вступят в силу после обычного перезапуска UI-сервера;
текущую задачу анализа не трогали. Не выполнялся массовый перенос всего
монолитного `app.js` в модули: это увеличило бы риск регрессии во время
действующей задачи.
