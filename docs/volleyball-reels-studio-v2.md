# Volleyball Reels Studio 2: инструкция

Дополнения: [управление на русском, тематический монтаж, 8 CPU и заметные эффекты без затемнения](volleyball-natural-language.md).

Проектный Skill установлен в `.agents/skills/volleyball-reels-studio/`. Код находится в `scripts/volleyball_studio/`. Для переноса нужен этот репозиторий, модели `models/`, `ov/` и Python-зависимости проекта. Существующее окружение и CUDA не переустанавливаются. Краткий запуск из WSL одной копируемой командой:

```bash
cd /mnt/c/Users/amazomic/Desktop/github/fast-volleyball-tracking-inference && PYTHONPATH=scripts .venv/bin/python -m volleyball_studio
```

Команда задаёт пять вопросов: итоговая длительность, минимальная длительность исходного розыгрыша, число роликов, стиль, музыка. По умолчанию: 30 с, 4 с, 1, dynamic, без музыки. Видео `.mp4`, `.mov`, `.mkv` и дополнительные форматы находятся непосредственно в `project/`. Вложенные папки со старыми результатами пропускаются.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/volleyball_studio/run.ps1
```

Windows-обёртка использует native `.venv/Scripts/python.exe`, если он есть, иначе Ubuntu-25.04 и `.venv/bin/python`. Дополнительные пути передавайте в формате выбранной среды.

Локальные навыки FFmpeg, media-analysis, Remotion и video-editing изучены; runtime использует OpenCV/FFmpeg напрямую для конкретного покадрового контракта. Внешние генеративные сервисы не нужны.

## Анализ один раз, монтаж многократно

Стадии: A Discovery, B Detection, C Game Analysis, D Highlight Selection, E Editing, F VFX, G Audio, H Rendering, I Quality Control. G/H исполняются одним FFmpeg-графом без лишнего повторного чтения; логические статусы сохранены отдельно. Каждый законченный этап проверяется хешами, каждый прерванный или ошибочный имеет status JSON. Незавершённый этап повторяется с начала; продолжения нейросети с произвольного кадра нет.

Обнаружение зависит от исходника, прокси, моделей, кода CV и параметров распознавания. Смена музыки, стиля, числа/длительности роликов, ручного отбора и минимальной длительности **не меняет результаты детекции**. Game Analysis отделён от отбора; базовая сегментация сохраняет треки от 1.5 с. Повторный монтаж использует прежний `--work`.

```bash
PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --non-interactive --style classic --duration 20 --music no
PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --non-interactive --style cinematic --duration 30 --music yes
```

В `studio_work/<source_fingerprint>/` находятся `analysis.mp4`, `source.probe.json`, `ball/analysis/ball.csv`, `players.json`, `tracks/analysis/tracks/`, `analysis/events.json`, `analysis/game-tracks.json`, `ranking.json`, complete/status-маркеры и журналы. Исходники не изменяются.

Каждый запуск создаёт отдельный каталог `studio_output/<run>/` с:

```text
videos/<video_name_id>/analysis/index.json
videos/<video_name_id>/reports/processing.json
previews/index.html
previews/highlights.json
previews/selection.json
selection.json
renders/classic|dynamic|cinematic/reel_01.mp4
renders/classic|dynamic|cinematic/reel_01.timeline.json
reports/reel_01.quality.json
manifest.json
```

Per-video index ссылается на независимый неизменяемый анализ в work; большие CSV/JSON не копируются в каждый новый монтаж. При ошибке одного видео остальные анализируются, ошибка попадает в manifest. Частичный результат возвращает ненулевой код завершения.

## События и отбор

`analysis/events.json` является единым источником контактов для VFX и акцентов. Каждое событие имеет id, source, track_id, frame, frame_domain, time_sec, type, ball, player_track_id, confidence, status, recommended_effect; при наличии измерений — speed_px_sec и direction_change_deg. Frame относится к явно указанному прокси CFR 30; time_sec содержит смещение исходника. Для VFR это не точный индекс исходного кадра. Координаты находятся в пространстве прокси с сохранёнными размерами; рендер масштабирует их в исходное разрешение.

Рейтинг содержит веса событий, ограниченный бонус длительности, число касаний, скорость мяча в ширинах изображения за секунду, изменения направления, смены сторон, динамику игроков и качество отслеживания. Длинная статика не считается зрелищной автоматически. Technical returns отбрасываются. Confidence и типы эвристические, не калиброванные вероятности. Без площадки confidence контактов умножается на 0.85, стороны неизвестны; serve/block не подтверждаются. Одинаковые копии исходного файла и перекрывающиеся эпизоды не выбираются повторно; семантический поиск всех похожих розыгрышей не реализован.

Целевая длительность — верхняя граница. Длинный эпизод обрезается вокруг игрового контакта с учётом типа и уверенности, а не только скорости. Короткому эпизоду добавляется до 8 кадров контекста с каждой стороны в пределах анализируемого участка и до соседних треков. Короткий материал всё равно может дать более короткий ролик с предупреждением; случайные паузы не добавляются для искусственного заполнения. При замедлении финальная карта ограничивается фактическим экспортом, QC предупреждает о близком к концу касании.

## Предпросмотр и ручной контроль

```bash
PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --non-interactive --preview-only
```

Откройте `previews/index.html`: он содержит миниатюры, таймкоды, оценки, confidence и ID. В `previews/selection.json` добавьте ID в include/exclude; пустой include означает все. Затем:

```bash
PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --non-interactive --selection-file studio_output/КАТАЛОГ/previews/selection.json --style cinematic
```

Это новый монтаж с прежним work, без нового распознавания. `--analyze-only` завершает работу после анализа и монтажного листа. Предпросмотр не блокирует автоматический экспорт.

## Камера, эффекты и звук

Камера учитывает траекторию, ближайшего игрока, сглаживание, ограничение скорости и короткое предсказание при потере мяча. Zoom около контакта меняется плавно. Используется один полноэкранный вертикальный кадр без обзорного окна и «картинки в картинке».

Classic: эффекты выключены, естественный звук. Dynamic: умеренные акценты, титр, цветокоррекция, ретайминг уверенных атак. Cinematic: процедурный огонь, затухание после атаки, шлейф, контактная вспышка, короткий shake, zoom и ретайминг. `--effects off/subtle/cinematic` переопределяет интенсивность. Модуль `vfx.py` отделён от рендера.

Огонь требует attack, confidence не ниже 0.75, скорости, рекомендации события и уверенного согласованного мяча в конкретном кадре. При потере мяча эффекты выключаются. Базовый bbox-guard подавляет огонь/шлейф при перекрытии с телом; это консервативная защита, а не сегментация и не восстановление глубины. Размер эффектов масштабируется с разрешением. Огненный эффект стилизован, фотореалистичная симуляция не заявляется.

Speed ramp: до сильного контакта 0.5×, затем естественная скорость и короткое ускорение 1.5×. Источник скорости — уверенное событие; при недостаточной уверенности скорость остаётся 1×. Аудио использует те же непрерывные интервалы и точное число выходных кадров, `atempo`, padding и trim, чтобы пропущенные видеокадры не вырезали случайные звуковые кусочки.

Исходный звук сохраняется. Музыка выбирается по имени либо `--music-file`; если её нет, используется исходный звук с предупреждением. Sidechain ducking включён, отключается `--no-ducking`. Громкости: `--match-volume 1`, `--music-volume .15`, `--accent-volume .5`. Лимитер ограничивает пики; полноценная двухпроходная LUFS-нормализация не выполняется. Видеопереходы используют zoom без затемнения; звуковые fade устраняют щелчки. Beat matching не заявляется.

## Производительность и диагностика

```bash
PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --doctor
PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --benchmark --input project
```

Benchmark использует реальные 10 секунд: холодный ONNX/OpenVINO, CPU/NVENC, чтение workspace против Linux tmp с учётом копирования. Отчёт содержит сырые секунды, оборудование и рекомендацию. Для короткого preview CPU может быть быстрее из-за инициализации GPU; не переносите этот вывод на длинные матчи и 1080p.

`--workers 0` выбирает до двух процессов, учитывая CPU и доступную RAM с бюджетом 4 ГБ на процесс. Параллелятся только независимые готовые эпизоды, нейросети работают последовательно. `--workers 1` ограничивает конкуренцию декодеров. RAM и GPU/VRAM фиксируются в отчёте. Жёсткий лимит VRAM библиотек и peak-profiler пока не реализованы.

`--scratch-dir /tmp/volleyball-studio` позволяет один раз скопировать прокси в Linux-кэш для обоих детекторов; добавляйте это по измерениям. Нормализованное декодирование переиспользуется; рендер читает оригинал. `--backend openvino` и `--encoder cpu` дают CPU-путь. Настоящая проба NVENC предшествует выбору кодировщика; auto возвращается к libx264 при ошибке.

Общий прогресс показывает A–I, обработанные видео, кандидатов, выбранные эпизоды, сегменты, готовые ролики, кодек, скорость и ETA. Во время загрузки ETA неизвестна; tqdm подпроцессов остаётся в журналах. SHA256 больших оригиналов выводит собственную скорость и ETA. Общая доля является весовой оценкой стадий, а не точным прогнозом времени.

## QC и восстановление

QC проверяет полное декодирование, MP4/H.264, 9:16, аудиопоток, синхронность длительностей потоков, карту кадров, длительные чёрные участки, допуск VFX и видимость мяча на ключевых контактах в основном вертикальном кадре. На ошибке выполняется одна попытка CPU-перекодирования; при повторной ошибке готовый файл не публикуется. Проверка чёрных кадров и повреждений выполняется по всему экспорту, не по миниатюрам. Равные хеши финальных роликов выявляют точные дубликаты.

Семантическая точность события, слышимая синхронность удара и видимость всех важных игроков не доказаны автоматическим QC. Отчёт прямо указывает эти границы. Для финальной оценки просматривайте видео и timeline.

`--resume <каталог_запуска>` с прежними параметрами переиспользует проверенные этапы. Изменение параметров требует нового каталога, но прежнего work. Исходники не удаляются. Общий work защищён блокировкой; не запускайте одновременно Windows и WSL против одного work. Старые результаты не перезаписываются.

## Площадка и ограничения моделей

Поддерживается ручной `<video_stem>_court.json` в формате `court_coordinates.py`; точки масштабируются и проверяются. Встроенной автоматической модели площадки нет. Исследован [Volleyball-Metrics](https://github.com/kairsato/Volleyball-Metrics): автор описывает автоматическую court calibration, но также провал broadcast-модели на бытовых широкоугольных записях. Эти веса не устанавливались и не объявляются подходящими для ваших пляжных матчей. Для полностью автоматической геометрии нужна отдельно проверенная court keypoint модель; для надёжной спортивной семантики — размеченная оценка и, вероятно, pose/action модель.

Повторно проверены [OpenVINO requirements](https://docs.openvino.ai/2026/about-openvino/release-notes-openvino/system-requirements.html) и [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html). NVIDIA здесь работает через ONNX CUDA/NVENC, OpenVINO проверен на CPU. Нативный Windows-инференс, TensorRT, HDR tone mapping и moving-camera calibration не объявляются протестированными.

Тесты: `PYTHONPATH=scripts .venv/bin/python -m unittest discover -s tests -v`. Фактические новые прогоны и сравнение производительности — в `volleyball-studio-validation-v2.md`.
