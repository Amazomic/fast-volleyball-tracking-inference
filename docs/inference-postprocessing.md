# Разделение инференса и постобработки (экспериментально)

## Проверенный конвейер
Подготовка видео: scripts/volleyball_ui/prepared_videos.py и scripts/volleyball_studio/video_inputs.py.
GPU: src/inference_onnx_seq_gray_v2.py (VballNet) и src/inference_player_ball_openvino.py (RAVEL).
CPU: src/track_calculator_with_court.py, src/player_contacts.py, scripts/volleyball_studio/analysis.py.
Монтаж: scripts/volleyball_ui/montage_runner.py режет оригинал, а не анализ-прокси.

## Команды
Нейросети без постобработки:
    python -m scripts.volleyball_studio --input match.mp4 --work studio_work --output studio_output --non-interactive --inference-only --player-model RAVEL-VB-013-9f --player-backend onnx-cuda --backend onnx
Повторная обработка без GPU:
    python -m scripts.volleyball_studio.reprocess --cache <cache-path> --mode ravel-touch --touch-threshold 0.5
Весь проект:
    python -m scripts.run_project_reprocess --project-id <id> --run-id <run-id> --mode combined --ball-threshold 0.55 --player-threshold 0.4 --touch-threshold 0.5

Режимы: baseline, ravel-touch, ravel-geometry, combined.

## Интерфейс и область действия настроек
- **Анализ**: параметры профиля используются при новом инференсе (GPU/CPU) и последующих стадиях, не меняют ранее сохранённые результаты. Карточка «Пересчёт» ведёт в единый редактор на вкладке «Предпросмотр»; отдельные дублирующие поля с вкладки «Анализ» убраны.
- **Предпросмотр → Только отображение**: видимость аннотаций и порог уверенности уже сохранённых событий — без изменения данных.
- **Предпросмотр → Пересчёт существующих результатов (CPU)**: порог VballNet (мяч), RAVEL (игроки), алгоритм и Touch (касания). Ползунки сразу фильтруют отображаемые точки/рамки, но сохранённые касания и границы розыгрышей меняются только после «Пересчитать проект». Пороги сохраняются для выбранного запуска и применяются ко всем видео проекта.
- В режимах baseline и ravel-geometry Touch не используется и поле блокируется; в режимах с источником мяча RAVEL порог VballNet не используется в CPU-расчёте.
- **Левый блок «ХОД ОБРАБОТКИ»**: одна задача CPU-пересчёта с видео, стадией, количеством завершённых шагов, общим процентом, временем и остановкой. Сервер публикует 5 реальных контрольных этапов на видео через UI_PROGRESS. Внутри длительной стадии точного прогресса по кадрам пока нет.
- Выбор запуска слева показывает, исходный ли это анализ или версия CPU-пересчёта.


Каждый результат — отдельный каталог postprocessing/<version-id> с events.json, game-tracks.json, ranking.json и track_*.json. Оригинальный анализ не перезаписывается.

## Ограничения совместимости
- Старый players.raw.jsonl содержит только рамки игроков. Новый players.raw.v2.jsonl сохраняет декодированные предложения игроков/мяча и вероятности действий, включая Touch, но НЕ полные тензоры сети.
- Часть кандидатов RAVEL отсекается декодером/NMS, поэтому смена frame-step, stride и других GPU-параметров требует нового инференса.
- ball.raw.csv VballNet хранит только максимум на кадр. Пересчёт с другим порогом использует фильтрацию сохранённых пиков (приближённо); точное восстановление контурного декодирования heatmap требует нового GPU-инференса.
- Порог игроков RAVEL при снижении использует сохранённые декодированные кандидаты v2, поэтому это не точный повтор исходного трекинга (возможны другие Track ID). При отсутствии v2 пересчёт ниже первоначального порога запрещён.
- Кэш старого формата без inference.manifest.json явно отклоняется при повторной обработке. Хэши данных проверяются перед запуском.
- Touch от RAVEL — гипотеза модели по кадру, не доказанное физическое касание. Тип сохраняется unknown_touch со статусом model_prediction.
- Реконструированные границы и новые ID розыгрышей НЕ отождествляются автоматически с исходными.
- Калибровка площадки и стартовая позиция видео должны быть совместимы с выбранным результатом.
- Верификация на реальных матчах и ручной эталон отсутствуют; корректность сравнительной точности не установлена.

## Зависимая цепочка в шапке
В шапке четыре выпадающих селектора: **Проект → Видео → Первичный анализ нейросетями → Версия обработки результатов (CPU)**.
- Проект задаёт допустимые видео; при переключении исходный анализ и все его CPU-версии перестраиваются по этому проекту.
- Видео задаёт текущую ветку. Результаты первичного анализа связаны с конкретным файлом через `videos[video]` и cache_id. Последний выбранный leaf-run хранится отдельно для пары «проект + видео».
- Первичный анализ показывает профиль, дату и сохранённый диапазон видео. Каждый успешный запуск — отдельная ветвь, даже если используется то же видео и тот же профиль. В новых запусках `analysis_timings/*.json` сохраняет `range_start` и `range_end`; последующая правка текущего диапазона не переписывает прошлый запуск.
- Обработка результатов показывает исходную версию и все дочерние `postprocess_settings` конкретного первичного запуска. Смена первичного анализа скрывает версии предыдущего; смена CPU-версии не запускает модель заново.
- Синхронизация действует между шапкой, левым выбором анализа, списком источников на вкладке «Анализ», «Предпросмотром», отчётом и монтажом. При выборе другого файла обновляются и выбранные для дальнейшей работы результаты.
- **Новый кусок того же видео**: выбрать/изменить временной диапазон на вкладке «Анализ» и выполнить новый первичный запуск. После успешного завершения он появится в третьем селекторе как отдельная ветка с собственным диапазоном и вариантами CPU-обработки.
- Старые завершённые запуски без записанных диапазонов не переименовываются по текущему диапазону; при наличии inference.manifest они могут показывать сохранённое смещение (начало), иначе подписаны как «диапазон не записан».
