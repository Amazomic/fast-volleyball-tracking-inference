# Непрерывность ID игроков: проверка 6 ноября 2026

Проверен текущий код и синтетические сценарии; качество на размеченном реальном матче не измерялось. Алгоритм трекинга в этой задаче не изменён.

## Что работает

CPU-пересборка в `scripts/volleyball_studio/replay_player_tracking.py` по умолчанию удерживает трек 90 кадров. При 30 FPS возврат через 90 кадров сохраняет ID, если рамка проходит пространственные ограничения. Через 91 кадр трек уже истекает. Параметр измеряется в кадрах: 90 кадров при 60 FPS дают 1,5 секунды.

`PlayerHysteresis` сопоставляет рамки глобальным венгерским алгоритмом по позиции, перекрытию и размеру. Существующие проверки пересечений и уникальности ID внутри кадра проходят. Слабая детекция может продлить существующий трек, но не открывает новый до порога уверенности.

## Ограничения

Это удержание ID и ограниченная экстраполяция, а не интерполяция между двумя достоверными наблюдениями. Скорость применяется максимум на восемь кадров. Затем рамка замирает; её уверенность умножается на `0.9 ** missing`. Через 90 кадров от исходной уверенности остаётся около 0,0076%.

В проверке игрок движется на 0,4% ширины кадра за кадр, пропадает на три секунды и возвращается на 36% ширины дальше. Старый ID не восстанавливается: пространство поиска недостаточно для такого перемещения. Увеличение одного времени удержания этого не исправляет. При появлении другого похожего по геометрии игрока рядом с потерянным возможна ошибочная связь: трекер не использует внешность для этого сопоставления.

Первичный GPU-трекинг имеет отдельный параметр `player_hysteresis_frames`, по умолчанию 60. Геометрические предложения `player_continuity.py` ограничены `min(20, round(fps * 0.7))` кадров и остаются неподтверждёнными; это ещё один самостоятельный механизм.

## Вывод и дальнейшее улучшение

Требование «восстановить того же игрока после любого разрыва до трёх секунд» текущая реализация не гарантирует. Для надёжного восстановления нужны раздельные сроки жизни ID и отображаемой рамки, сопоставление потерянных треков по внешности с проверкой неоднозначности и, при наличии обоих концов разрыва, заполнение траектории. Проверять это следует на размеченных перекрытиях и пересечениях с подсчётом смен ID; расширять пространственный радиус без дополнительного подтверждения рискованно.

## Воспроизводимые проверки

`python -m unittest tests.test_player_three_second_gap tests.test_player_id_stability tests.test_raw_player_replay -v`

Покрываются граница 90 кадров, истечение, замершая рамка, значительное перемещение, пересечения и CPU-пересборка с сохранением исходных ID.
