# Проверка Volleyball Reels Studio — 29 октября 2026

## Окружение

Windows PowerShell 5.1 → WSL Ubuntu-25.04, Linux 6.18.33.2, Python 3.14.7, OpenCV 5.0.0, ONNX Runtime 1.31.1, OpenVINO 2026.2.1, FFmpeg 7.1.1. NVIDIA GPU: 12227 MiB по nvidia-smi; driver 615.71.08, KMD 616.92. CUDA smoke test выполнил три настоящих вызова VballNetV4c. Сессия использовала CUDAExecutionProvider и CPUExecutionProvider. Проверка NVENC настоящим кодированием кадра прошла. OpenVINO обнаружил только CPU.

Нативное Windows Python-окружение отсутствует: проверена Windows-обёртка с запуском через WSL, а не нативный Windows-инференс. TensorRT присутствует в списке ORT, но не использовался и не проверялся. Пакеты среды автоматически не переустанавливались.

## Реальные прогоны

1. Обработаны первые 25 секунд каждого из трёх видео в project (всего 2250 кадров анализа). До монтажа дошёл один уверенный кандидат; два других фрагмента не получили достаточной оценки. Получен ролик 360×640, H.264/AAC, 8 секунд. После исправления синтаксиса FFmpeg прогон завершился без ошибок.
2. Изолированный 25-секундный фрагмент с исходным звуком → 1080×1920, 30 fps, H.264/AAC stereo, 8 секунд, 240 кадров. Полный первоначальный прогон занял 57.32 с. Проверка восстановления через Windows-команду заняла 5.08 с: normalize, ball, players, tracks, segment и export были взяты из кэша, MP4 не перезаписан. В этом раннем демонстрационном фрагменте зарегистрировано 4 кадра огня/замедления, 13 кадров шлейфа, 1 кадр вспышки. Визуальная проверка выявила подготовку перед игрой, которую эвристический рейтинг переоценил. Этот результат не представлен как успешный семантический выбор зрелищного розыгрыша.
3. Более подходящий 30-секундный фрагмент с позиции 00:01:35 оригинального VID_20261024_180739.mp4 → два кандидата. Выбранный эпизод: score 23.4721. Финальная демонстрация с обзорным окном: `studio_demo_final/20261029_204123_918060_a71117/reel_01.mp4`, 1080×1920, 30 fps, H.264/AAC, 8 секунд. Создание с готовым CV-кэшем заняло 15.72 с. На этапе камеры измерено около 41 кадр/с. Огонь и замедление в выбранном фрагменте не допущены порогом; в предыдущем экспорте этого же эпизода было 1 срабатывание шлейфа и 4 кадра вспышек. Отсутствие уверенного attack не заменялось искусственным эффектом.

В каждом экспорте выполнены FFprobe и полное декодирование FFmpeg с `-xerror`. Длительность, codec, размер и аудиопоток проверены программно. Просмотрены контактные листы исходника и результатов. Итоговая timeline содержит конкретный источник и время каждого из 240 выходных кадров.

Окончательный запуск повторно восстановлен через PowerShell → WSL за 4.69 с: все этапы взяты из кэша, MP4 не перезаписан. Дополнительный реальный прогон с `--count 2 --duration 5 --effects off --encoder cpu --width 360` создал два отдельных ролика без ошибок за 7.50 с с готовым CV-кэшем. Визуально проверен окончательный контактный лист с обзорным окном; широкий игровой контекст сохранён, но основной crop местами следует неточной траектории. Это ограничение детектора, а не подтверждение точности виртуальной камеры на всех матчах.

Замеры на первом фрагменте: VballNet CUDA около 109 кадров/с по tqdm; RAVEL OpenVINO CPU 98.34 кадров/с с декодированием и постобработкой, 141.02 кадров/с для model portion. Отдельный VballNet OpenVINO CPU прошёл на 750 кадрах, около 99.52 кадров/с. Эти числа относятся к коротким фрагментам и не гарантируют такую скорость на полном матче. Хеширование оригиналов объёмом примерно 12.5 ГБ входит в время запуска; SHA256 теперь выводит скорость и ETA.

## Автоматические проверки

Семь тестов прошли: шесть unit и один интеграционный. Интеграционный тест реально создаёт видео и проверяет CPU-кодирование, огонь на заданных координатах, повторы исходных кадров при замедлении, аудио той же длины, музыку, звуковой акцент, переход между двумя эпизодами, источник без аудио и обзорное окно при потере мяча. Синтетические координаты теста не используются как доказательство точности распознавания спорта.

Штатный `quick_validate.py` подтвердил `Skill is valid!`; PyYAML запускался в изолированном окружении uv. Код прошёл compileall. В добавленных кодовых файлах нет комментариев. Пользовательское изменение src/inference_onnx_seq_gray_v2.py и прежние локальные монтажные скрипты сохранены.

## Что остаётся ограничением

Это работающий локальный конвейер с проверенным полным циклом, но качество автоматического спортивного отбора пока не подтверждено размеченным датасетом ваших матчей. Был наблюдён ложноположительный выбор подготовки. Геометрия без court JSON отсутствует; техника контакта остаётся эвристической; без геометрии неизвестны стороны, подачи и блоки. Надёжная полностью автоматическая разметка площадки потребует дополнительной court keypoint модели, а спортивная семантика может потребовать pose/action модели и размеченной проверки.

Путь с ручным court JSON не проверялся на этих реальных исходниках, поскольку соответствующая разметка не предоставлена. Разметку из чужого ракурса или заранее заданные точки не подставляли.

Процедурный огонь является стилизацией. Автоматическая LUFS-нормализация, HDR tone mapping и компенсация движущейся камеры не реализованы. Внешние сервисы не требуются для реализованных функций. Длинные исходники целиком не прогонялись; проверен полный набор этапов на коротких фрагментах, а не весь объём матчей. Восстановление работает по завершённым этапам, без продолжения инференса с произвольного кадра.
