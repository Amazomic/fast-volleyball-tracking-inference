# Volleyball Studio — архитектура дорогого инференса и дешёвой интерпретации

**Обязательное проектное решение: 2026-11-06.**
**Основной контент:** любительский волейбол; состав игроков меняется редко.

## Контракт

GPU исполняет обученные модели только один раз для каждой комбинации исходного
видео, модели, входного разрешения и временного диапазона. Его задача —
сохранить максимально полезные неизменяемые доказательства, а не выбрать
единственный вариант трактовки. Изменение порогов Touch, мяча, игроков,
ReID, сборки треков или розыгрышей НЕ должно запускать GPU, если нужные
доказательства уже сохранены.

1. **Подготовка:** единый переиспользуемый прокси видео, вне проектов.
2. **GPU:** VballNet сохраняет обнаружения и сырые оценки пиков мяча.
   RAVEL-013 сохраняет players.json (совместимый пороговый результат),
   players.raw.v2.jsonl (слабые предложения, бокс, оценка, Touch и
   временные ссылки запросов), players.raw.json (метаданные порога).
   В новых анализах минимум для кандидатов игроков 2%, до CPU NMS.
   Данные GPU не перезаписываются CPU-версией.
3. **CPU:** пороги, NMS, устойчивые Track ID, сопоставление с оригинальными
   GPU ID, ReID по нескольким снимкам, автопривязка с защитой от ошибок,
   Touch-пики, геометрия, розыгрыши, персональная статистика. Каждое
   изменение даёт независимую версионированную CPU-ветвь.
4. **Предпросмотр:** по умолчанию рекомендуемая завершённая CPU-ветвь
   (VballNet + Touch RAVEL + геометрия, Touch 45%, игроки 30%).
   Сырые обнаружения моделей доступны отдельно для диагностики.
   Новые настройки сохраняются в новой CPU-версии только после пересчёта.
5. **Монтаж:** конкретная CPU-версия + исходное видео, без GPU.

## Нельзя нарушать

- CPU не придумывает обнаружения, которых нет в GPU-кэше. Интерполяция
  допустима только между настоящими наблюдениями и должна быть помечена.
- Исходные GPU Track ID неизменны. CPU-трекинг пытается сохранить их по
  геометрическому подтверждению; новым трекам выдаёт отдельные ID.
- Два человека, видимых одновременно, не могут быть одной личностью.
- Группировка Track ID не равна назначению реального игрока. Ручное
  подтверждение выше любой автопривязки; автоответы не служат эталоном.
- Удалённая вручную автопривязка не создаётся повторно без согласия.
- Число игроков нельзя подгонять к 5 без независимых наблюдений.
- Косинусное сходство ReID — не калиброванная вероятность.
- Длительная пауза только предполагает границу игровой сессии; смена сторон
  и конец партии требуют отдельного детектора.

## Границы возможности

Raw v2 хранит декодированные кандидаты и Touch, не полные GPU-тензоры.
Кадры, пропущенные моделью, или боксы ниже минимума восстановить на CPU
нельзя. Старые результаты могут иметь минимум 5%, UI показывает их
реальный минимум. Смена модели/разрешения/входного видео требует GPU.

GPU кэш текущих старых запусков всё ещё учитывает некоторые параметры
первичного трекера. При развитии архитектуры необходимо вынести их
полностью в CPU и не менять нейросетевой кэш из-за настроек сопоставления.

## Реализация и тестирование

- src/inference_player_ball_openvino.py — сырые декодированные детекции.
- scripts/volleyball_studio/inference_cache.py — манифест неизменяемого GPU.
- scripts/volleyball_studio/replay_player_tracking.py — CPU Track ID.
- scripts/volleyball_studio/reprocess.py — CPU-пересчёт и версии.
- scripts/run_project_analysis.py — после GPU рекомендуемая CPU-версия.
- scripts/volleyball_ui/player_identity_groups.py — ReID / группировка.
- scripts/volleyball_ui/rally_players.py — реальное и восстановленное присутствие.
- scripts/volleyball_ui/static/results-ui.js — предпросмотр и параметры.
- scripts/volleyball_ui/static/analysis-presets.js — пресеты анализа.

Метрики качества: recall игроков, ложные/разорванные ID, точность касаний,
устойчивость между розыгрышами, длительность CPU-пересчёта. Результаты на
размеченных матчах не подменять оценками на синтетических тестах.
