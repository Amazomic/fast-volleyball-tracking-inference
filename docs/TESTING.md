# Стадии проверки Pull Request

CI: `.github/workflows/pr-quality.yml`; длительный регресс:
`.github/workflows/extended-regression.yml`; GPU проверка только вручную:
`.github/workflows/gpu-acceptance.yml`.

| Стадия / job | Триггер | Что блокирует |
| --- | --- | --- |
| 01 / Structure and policy | Каждый PR | Синтаксис Python, нарушенная структура, секреты/данные, несогласованный золотой профиль, тесты policy |
| 02 / Browser logic (Node) | После 01 | Синтаксис JS, фильтры, состояние UI, предпросмотр и привязки без реального браузера |
| 03 / CPU domain regressions | После 01 | Touch motion, Track ID, ReID, золотые значения, формирование розыгрышей |
| 04 / Project-to-reel contracts | После 01 | Разделение GPU/CPU, история проектов, повторная обработка, Quick Reel, исходное качество монтажа |
| 05 / Docker deployment smoke | Если изменены Docker/зависимости/UI backend entrypoint; всегда при ручном запуске | Сборка и доступность `/api/health` внутри контейнера |
| 06 / Merge gate | Каждый PR (даже при сбоях) | Любой неуспешный обязательный job либо неуспешный Docker, если он требовался |
| Extended regression | Раз в неделю или вручную | Полный Python suite, Node tests и Docker boot (наблюдение; не подменяет PR gate) |
| GPU acceptance | Ручной dispatch, защищённый `volley-gpu` runner | Проверка устройства и inference/benchmark проекта с реальным видео; необходима при изменении моделей/входных данных |

PR-проверки запускаются параллельно после быстрого preflight.
Docker не компилируется при каждом изменении CSS/документа, если не тронут
его контракт запуска. Для GPU не используется публичный GitHub runner:
нужны NVIDIA drivers/Toolkit и разрешённые локальные данные.

## Локальная проверка

```bash
python -m compileall -q main.py src scripts
python scripts/ci/repo_policy.py
python -m unittest discover -s tests -p test_ci_quality.py -v
node --test tests/*.cjs
uv sync --frozen --extra dev
PYTHONPATH=.:src uv run --no-sync pytest -q tests
```

Стадия проверки **качества** не равна количеству прошедших мок-тестов.
Unit-тесты защищают инварианты, но реально измерить Touch и качество
монтажа можно только на одинаковых материалах. См.
[quality/README.md](quality/README.md).

## Регрессионные пользовательские сценарии

1. Создать проект, добавить совместимый и несовместимый файлы, получить
   готовый прокси **один раз** и не дублировать на повторной загрузке.
2. Сохранить GPU-вход и запустить 2 CPU-версии с разными настройками:
   входные данные должны остаться побайтно неизменными.
3. Поменять Track ID, вернуть скрытого игрока, проверить разрыв до 3 сек,
   отсутствие ложного слияния одновременно видимых людей.
4. Считать Touch только с подтверждением изменения траектории/скорости,
   проверять ложные пересечения; корректно строить границы розыгрышей.
5. Переключить проект, исходное видео, GPU-run и CPU-run без потери
   предыдущего выбора; F5 не запускает дорогой инференс заново.
6. Создать Quick Reel отдельно от проекта, исходники не перезаписаны,
   финальный монтаж использует оригинальное видео.
7. Отменить задачу и повторить, безопасно удалить неактивный результат;
   проверить видео, аудио, таймкод, FPS и ориентацию.

Еженедельный прогон полной матрицы может выявить проблемы за пределами
нацеленных PR-тестов — такие находки оформляются отдельным исправлением.
