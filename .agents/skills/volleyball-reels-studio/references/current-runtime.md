# Подробности текущего конвейера

Основной SKILL.md определяет обычный запуск. Этот справочник содержит подробные параметры существующей реализации, а не подтверждение готовности целевого CLI.


Используй для локального волейбольного монтажа в репозитории fast-volleyball-tracking-inference. Реализация: `scripts/volleyball_studio/`; актуальная инструкция и ограничения: `docs/volleyball-reels-studio-v2.md`. Это проектный Skill: при переносе нужен весь репозиторий с моделями. Не переустанавливай CUDA или существующее Python-окружение без доказанной необходимости.

При каждом запуске Skill до обработки показывай пользователю краткое напоминание о фактических параметрах анализа следующей таблицей. При переопределении разрешения, FPS или моделей указывай реальные значения запуска вместо базовых. Не выдавай эвристические события за подтверждённые.

| Что | Параметры анализа |
| --- | --- |
| Видео | Уменьшенная копия 1280×720, 30 кадров/с |
| Мяч | VballNet V4c: координаты, уверенность обнаружения, траектория и скорость |
| Игроки | RAVEL-VB-012: рамки игроков и идентификаторы треков |
| Игровые эпизоды | Разделение траекторий на розыгрыши и неигровые участки |
| Касания | Эвристическая оценка по движению мяча и расположению игроков |
| Зрелищность | Скорость мяча, число и типы касаний, изменения направления, длительность и качество отслеживания |

Исходные видео и музыку бери из непосредственных файлов `project/`. Все новые промежуточные данные анализа сохраняй в `results/analysis/`, готовые ролики, монтажные планы, предпросмотры и отчёты — в `results/reels/<каталог запуска>/`. При каждом вызове CLI явно передавай `--input project --work results/analysis --output results/reels`: встроенные значения CLI могут указывать на прежние каталоги. Старый проверенный кэш можно скопировать в `results/analysis/` для повторного использования без нового распознавания; старые результаты не удаляй. Для повторного монтажа сохраняй этот же `--work`.
При разработке или изменении анализа, монтажа либо VFX прочитай [контракт интеграции событий, монтажа и VFX](references/events-editing-vfx.md). Он задаёт обязательные артефакты, обнаружение установленных Skills, преобразования координат и времени, проверки и демонстрационный тест. Это требования к исполнению, а не утверждение, что текущий CLI уже реализует весь контракт. Если реализация отстаёт, явно укажи пробелы; существующие ограничения ниже не отменяют контракт. Изменение самого Skill не означает поручение реализовать pipeline или запустить рендер.

Сначала извлеки условия из свободного запроса на русском языке: события и их сочетания, общую целевую длительность, число готовых монтажей, стиль, интенсивность эффектов и требования к звуку. Не задавай повторно вопросы, ответы на которые уже есть в запросе. Уточняй только важную неоднозначность, для остальных пропусков используй разумные значения. Базовые параметры: итоговая длительность (30 с), минимальный исходный розыгрыш (4 с), число роликов (1), стиль classic/dynamic/cinematic (dynamic), музыка (нет). Уже сообщённые ответы не спрашивай повторно. Затем запускай с `--non-interactive` и явными параметрами. Самостоятельный CLI задаёт те же пять вопросов. Интенсивность `--effects off/subtle/cinematic` является дополнительным переопределением стиля.

Перед монтажом уточни одним сообщением два независимых параметра, если пользователь ещё не указал их: «Нужны ли подписи к видео? Если да, какой текст?» и «Добавлять ли эффекты для мяча?». Явный запрос на эффекты для мяча или конкретную подпись уже считается ответом; не спрашивай повторно. Общий запрос «с эффектами» не уточняет, нужны ли именно эффекты для мяча. Дождись ответа перед применением этих элементов; пока можно обнаруживать исходники и выполнять анализ. Отсутствие ответа не означает согласия.

Не добавляй подписи, титры, название стиля, водяные знаки и служебный текст без явного запроса. В частности, надпись `VOLLEYBALL | DYNAMIC` не должна появляться автоматически. Выбор Dynamic или Cinematic сам по себе не разрешает ни подписи, ни эффекты для мяча. Перед рендером явно отключай автоматические `titles`, если подписи не заказаны: текущие пресеты могут включать их самостоятельно. Если подписи нужны, используй только согласованный текст. При отказе от эффектов для мяча отключай огонь, шлейф, вспышки и другие привязанные к мячу эффекты независимо от выбранного стиля. Эти два вопроса задаёт агент дополнительно к базовым вопросам самостоятельного CLI; не полагайся на несуществующие CLI-флаги.

WSL из корня репозитория: `PYTHONPATH=scripts .venv/bin/python -m volleyball_studio --input project --work results/analysis --output results/reels`.

Windows: `powershell -ExecutionPolicy Bypass -File scripts/volleyball_studio/run.ps1 --input project --work results/analysis --output results/reels`.

Перед первым производственным запуском выполни `--doctor`; для сравнения реальных путей обработки — `--benchmark --input project`. Наличие CUDA EP не доказывает работоспособность: doctor запускает инференс. OpenVINO CPU и NVIDIA CUDA/NVENC — разные пути. Не экстраполируй холодный benchmark 10 секунд на полный матч.

A Discovery → B Detection → C Game Analysis → D Highlight Selection → E Editing → F VFX → G Audio → H Rendering → I Quality Control. Отдельные маркеры и SHA256 проверяют завершённые этапы. Музыка, стиль, длительность и минимальная длительность отбора не должны запускать нейросети повторно. Меняй только параметры монтажа; сохраняй прежний `--work`. Готовые анализ и `analysis/events.json` являются источниками данных для повторного экспорта.

Видео и музыка обнаруживаются среди непосредственных файлов `project/`; вложенные старые результаты исключены. Источники не меняй и не удаляй. Результаты и кэш держи вне папки исходников. Обычный запуск создаёт новый каталог; `--resume <каталог>` с прежними параметрами восстанавливает прерванный. Не обходи отказ перезаписи. После изменения параметров создай новый запуск с тем же work.

`--preview-only` создаёт HTML-монтажный лист с миниатюрами, таймкодами, score и ID. Для ручного выбора отредактируй include/exclude в `previews/selection.json` и передай `--selection-file <файл>` при новом запуске. Пустой include означает все эпизоды. Полностью автоматический запуск не требует просмотра.

Используй существующие VballNet, RAVEL, court-aware калькулятор и player_contacts, не переписывай их алгоритмы. `events.json` хранит эвристические контакты, confidence, игрока, координаты, скорость и рекомендуемый эффект. Кадры событий относятся к явно указанной шкале analysis CFR 30; time_sec учитывает смещение исходного фрагмента. Не называй их точными индексами кадров VFR-оригинала.

Без `<video_stem>_court.json` не придумывай сетку и стороны. Классификация эвристическая, уверенность контактов снижается; подача и блок не подтверждаются. Автоматическая court-модель не поставляется; исследование внешних моделей и ограничений находится в документации. Самостоятельно не загружай непроверенные веса.

VFX и ретайминг допускаются только при уверенном согласованном мяче. Огонь требует уверенного attack, скорости и рекомендации события; скорость сама по себе не доказывает атаку. Bbox-guard подавляет огонь и шлейф на перекрытии тела, но не является точной сегментацией. При потере мяча эффекты прекращаются. Используй один полноэкранный вертикальный кадр. Не добавляй обзорные окна и «картинку в картинке».

При отсутствии музыки экспортируй исходный звук с предупреждением. Ducking музыки включён; `--no-ducking` его отключает. Звук замедлений/ускорений должен следовать той же карте времени, что и видео.

Проверяй manifest, reports/*quality.json, статусы, timeline и контактные кадры. Не объявляй MP4 готовой до QC. QC проверяет декодирование, геометрию, чёрные участки, потоковые тайминги аудио, карту кадров и допуск эффектов; семантическая точность и слышимая синхронность ударов требуют просмотра. Сообщай фактические длительность, число роликов, кодек, скорость, ошибки и ограничения. Отсутствие уверенных эпизодов не заменяй случайной нарезкой.

Тематический монтаж: «только атаки» → --events attack, «только блоки» → --events block, «лучшие подачи» → --events serve, «длинные розыгрыши» → --long-rallies; допускаются сочетания. Порог события --event-confidence 0.75. Несколько типов означают объединение, условие длинного розыгрыша — дополнительное ограничение. Если пользователь требует другую логику сочетания, уточни её. Не подменяй недостающие атаки, блоки или подачи другими событиями. Без геометрии не подтверждай блоки и подачи.

«Ролик на 30 секунд» означает один готовый монтаж на целевые 30 секунд из нескольких эпизодов, а не отдельный 30-секундный файл на каждый эпизод. Число готовых монтажей регулирует --count, по умолчанию 1. Автоматически выбирай последовательность и длины фрагментов, контекст удара, точки ретайминга, движение переходов и звуковые акценты. Не обрывай важное действие ради точной длительности, когда доступен контекст. Если материала недостаточно, сообщи фактическую доступную длительность и не заполняй её неподходящими событиями.

Общий CPU-бюджет по умолчанию 8: --threads 8 и наследуемое ограничение affinity. Это не восемь процессов монтажа. Используй другой бюджет только по явному запросу или при меньшем числе доступных CPU. При смене условий отбора нейросети повторно не запускай.

Не используй затемнение изображения для переходов. Применяй плавное движение/zoom; звуковое сглаживание допустимо. Эффекты должны быть заметнее и продолжительнее: огонь до 1 с, вспышка около 0.27 с, шлейф до 18 кадров, shake около 0.3 с, при наличии уверенного мяча. При потере достоверной траектории прекращай эффект, даже если плановое время не истекло. Режим off остаётся без художественных эффектов.

Актуальные примеры: docs/volleyball-natural-language.md. Локальный --request разбирает распространённые формулировки; полноценное понимание произвольного текста выполняет агент и передаёт явные CLI-параметры. Для проверки интерпретации без обработки используй --request "..." --plan-only.
