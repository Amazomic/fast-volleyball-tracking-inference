# Контракт автономности

Требования к инструментам skill. Изменение этого документа не поручает разработку приложения и не подтверждает готовность функций. Обычный запуск использует фактически доступный интерфейс; пробелы сообщаются кратко.

## Единый CLI

Рекомендуемая реализация: Python argparse или Typer. Интерфейс `volleyball_studio`:

| Команда | Назначение |
| --- | --- |
| create | Полный цикл создания Reels |
| analyze | Анализ видео и построение индекса |
| events | Фильтрация событий по типу, confidence, зрелищности и пригодности; сортировка по Highlight Score и ограниченная выдача |
| render | Повторный монтаж без анализа кадров |
| status | Короткий статус конкретного запуска |
| inspect | Краткая диагностика и пути логов |
| validate | Контроль качества |

Каждая команда поддерживает --help, --quiet, --verbose, --json, машиночитаемый отчёт и понятные ошибки с ненулевым кодом при сбое. По умолчанию stdout содержит компактный JSON: статус, число обработанных видео, число найденных событий, пути результатов и отчёта, ошибки и предупреждения. Подробные логи пишутся в файл. Пользователь видит прогресс в терминале через stderr; quiet подавляет его, verbose не нарушает машинный stdout. Ограничивай размер вывода, ошибки и фрагменты логов; полные выборки сохраняй в файл.

Пример выборки: attack с confidence >= 0.8, сортировка по Highlight Score. Если score относится к розыгрышу, явно укажи это; не выдавай его за оценку отдельного контакта. LLM получает только нужные метаданные событий.

## Индекс, пресеты и монтажный план

Предварительный компактный индекс хранит ID источника, события и розыгрыша, тип, исходное время, confidence, Highlight Score, пригодность, ограничения и ссылки на траектории. Фильтрация локальная; координатные массивы агенту не передаются. Рендерер сам читает нужные траектории.

Проверенные пресеты classic, dynamic, cinematic хранят параметры эффектов, переходов, звука, замедлений и рендеринга в YAML или JSON. Worker выбирает пресет и доступные переопределения вместо создания новой реализации монтажа.

Python-модуль автоматически создаёт edit_plan.json по типам событий, длительности, числу роликов и стилю: выбранные ID, порядок, интервалы исходника, ретайминг, кадрирование, звуковые акценты, зависимости и достижимая длительность. LLM не выбирает интервалы при достаточных данных. При неоднозначности модуль возвращает краткую диагностику и только необходимые данные для решения.

## Кэш и возобновление

Кэшируй стадии отдельно. Ключи учитывают версию анализатора, фактически выбранную модель, параметры, сведения об исходнике, контрольные суммы и зависимости стадии. Проверяй содержимое артефактов, а не только наличие файлов.

- Анализ кадров: исходник, модель и параметры анализа.
- События и индекс: анализ, геометрия, версия классификатора.
- План: индекс, фильтры, длительность и стиль.
- Сегменты: интервалы, траектории, камера, VFX, ретайминг и кодек.
- Звук и сборка: сегменты, музыка, громкости и ducking.
- QC: итоговый файл, карта времени и версия проверок.

Изменение музыки повторяет только звук, сборку и зависимые проверки; VFX переиспользует анализ. Атомарные состояния и маркеры завершения обеспечивают безопасное возобновление. Частичные результаты не принимаются за готовые. Возобновление проверяет параметры и зависимости. Устаревший кэш обнаруживается явно; render не запускает скрытый инференс.

## Другие skills

При разработке изучай доступные FFmpeg, Remotion и VFX skills и закрепляй проверенные решения в локальных модулях. Обычное создание ролика не требует их повторного чтения. Специализированный skill нужен для нестандартного эффекта, отсутствующей функции или изменения реализации. Не заявляй использование отсутствующего или непрочитанного skill.

## Тест эффективности

Отдельный тест сравнивает прежний и новый сценарии на одинаковых исходных данных и запросе. По фактическим трассам измеряй число обращений агента к инструментам, объём ответов в байтах, повторные чтения документации и JSON, число ручных решений, которые можно перенести в код. Сохраняй метод измерения, результаты и ограничения в кратком отчёте.

Цель после необходимых уточнений: один запуск CLI и максимум одно чтение краткого итогового отчёта, без полных треков в контексте, ручного плана и FFmpeg-команд. Новые эффекты требуют согласования внешнего вида и предложения сохранить; библиотечные применяются без генерации.

Синтетический тест CLI не является измерением токенов живого агента. Без baseline отмечай отсутствие данных. Конкретное сокращение токенов без измерений не утверждай.

## Критерий готовности

После первичной обработки матча запрос «Сделай один Reels на 30 секунд только из атак, добавь огненный мяч, музыку и замедления» выполняется готовым CLI без повторного анализа кадров, чтения агентом всех треков и ручных FFmpeg-команд. Локальный модуль строит план, рендерер читает траектории и создаёт MP4 с кратким QC-отчётом. Новый внешний вид предварительно согласуется; сохранённый эффект используется повторно. Не объявляй сценарий работающим без фактической проверки.
