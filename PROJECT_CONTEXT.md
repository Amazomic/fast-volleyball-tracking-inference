# Контекст проекта: Volley Studio

## Главная цель
Создать лёгкий, понятный и наглядный интерфейс для быстрого создания вертикальных рилсов (Reels, 9:16) из видеозаписей волейбольных игр.

## Продуктовый приоритет
Ключевая ценность — удобный процесс создания готового ролика, а не сложность используемых алгоритмов. Анализ матчей, отслеживание мяча и игроков и выделение розыгрышей должны помогать пользователю, а не усложнять работу.

## Принципы при разработке
- Простота: минимум обязательных действий и технических настроек для типового сценария.
- Наглядность: понятные превью, таймлайн и обратная связь о том, что попадёт в ролик.
- Контроль: пользователь может проверить и поправить автоматический выбор эпизодов.
- Скорость: избегать ненужных тяжёлых этапов при анализе, предпросмотре и экспорте.
- Надёжность: воспроизводимый результат и ясные сообщения об ошибках.

## Модель игроков и данные для будущего Re-ID (2026-11-01)
- **Игрок — глобальная сущность Volley Studio**, доступная во всех проектах. Реестр: `results/players/registry.json`; у каждого игрока стабильный `player_id`, который не зависит от Track ID и названия.
- При создании/редактировании проекта можно выбрать состав из глобального реестра. Список `player_ids` хранится в `results/projects/<project_id>/project.json`. Игрок может одновременно участвовать в нескольких проектах.
- **Track ID локален для конкретной записи и её анализа**, никогда не считается глобальной идентичностью. Подтверждённые человеком связи `player_id ↔ (project_id, video, track_id)` хранятся в `results/projects/<project_id>/player_identities.json`.
- Пользователь может массово выбрать до 200 Track ID и присвоить одному игроку, переназначить или снять привязку. Старые разметки импортируются, но автоматическая сверка личности по лицу ещё не реализована.
- После ручного присвоения ID фоновый поток пытается собрать до трёх качественных кропов на Track ID из сохранённого анализа и складывает их в `results/players/<player_id>/photos/*.jpg`. Метаданные — `results/players/<player_id>/index.json`: источник видео, проект, frame, track_id, confidence, пометка ручного подтверждения. При переопределении связи образцы предыдущего игрока для соответствующих Track ID удаляются.
- Фото не генерируются, если в результатах анализа отсутствуют достаточные предсказания или декодируемый `analysis.mp4`; это не ошибка разметки. **Дообучение сети и автоматическая идентификация ещё не реализованы**. Для последующего обучения нужен отдельный контролируемый экспорт, проверка разметки, разрешения на использование изображений и train/validation split по матчам, а не по отдельным кадрам.
- Цель следующего этапа: сборка персонального рилса по действиям и взаимодействиям с мячом через глобальный `player_id` и привязанные ему видео-треки.
